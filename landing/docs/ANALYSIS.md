# 랜딩 설계 분석 — Vencubator × TTJ 모션 문법

기준일 2026-09-24 · 대상: `landing/` · 연결 명세: [SPEC-006](SPEC-006-landing.md)

이 문서는 **왜 이렇게 설계했는가**를 남긴다. 무엇을 만들어야 하는지(계약)는 SPEC-006이 권위다. 관찰과 추론을 구분해 적는다.

## 1. 기존 Vencubator 분석

## 2. TTJ(ttj.kr) 섹션 구조·모션 분석

2026-09-24 실제 페이지를 브라우저로 열어 DOM/CSS/스크립트를 관찰했다. 코드는 복사하지 않고 **기법만** 재구현한다.

| TTJ 섹션 | 관찰한 기법 | 수치(관찰) |
|---|---|---|
| 고정 헤더 + 로컬 챕터 내비 | 상단 fixed, 섹션 앵커 목록, 현재 챕터 번호 `01 / 05`, 전체 진행 막대 `scaleX(p)` | 마커 = scrollY+190 |
| Hero | 스크롤 진행 p로 1행 축소·흐려짐, 2행 확대, 보조문 페이드아웃, 미디어 scale↑·radius↓·shadow↑ | p = (scrollY−top)/(height×0.62) |
| Type story (`#journey`) | 높이 ~3100px 섹션 안 sticky 100svh 스테이지. 3개 문장이 순서대로 확대/축소 교차, `01/03` 인덱스, “Scroll to build” | 구간: 1행 out .03~.32, 2행 in .18~.42 out .54~.73, 3행 in .61~.84 |
| Proof | IntersectionObserver `.tb-reveal → .is-visible`, 자식 0.06s 단위 stagger | threshold .09, rootMargin -40px |
| Route map | READ→CHOOSE→BUILD→EARN 4단계 연결 경로 + 화살표 | 정적 + reveal |
| 21 methods grid | 카드 그리드, 카드별 IO reveal, 호버 이미지 확대 | threshold .12 |
| Bridge `21 → 05` | sticky 스테이지에서 from 숫자는 작아지고 흐려지며, to 숫자는 커지며 도착, 화살표 회전 | arrive = smooth((p−.08)/.7) |
| Story (5단계) | sticky 스테이지 위 5 frame 교차. 제목 blur→선명, 상세 지연 등장, 우상단 `03 / 05`, 점 인디케이터 | position = p×(n−1), 전환점 .56 |
| Difference | 3카드 stagger, 호버 시 -8px | delay .08s |
| Schedule | 뷰포트 중앙 근처 행에 초점: 불투명도·x이동·is-current | focus = 1−|center−.54vh|/.58vh |
| Book | 패럴랙스 회전 | −3° → +2.5° |
| Sticky CTA | 히어로를 지나면 하단 CTA 바 등장, 마지막 CTA 근처에서 숨김 | final top < .78vh |
| 공통 | 모든 모션 rAF 1회 스로틀, `prefers-reduced-motion`이면 전부 정적 표시, smoothstep 이징 | `v*v*(3−2v)` |

## 4. 추론·미확정

- 전환 목표: 현재 실제 가입/대기 명단 백엔드가 없다. Primary CTA는 **로컬 프로토타입 체험**으로 두고, 대기 명단은 SPEC-006 DR-L01로 남겼다.
- 실제 사용자 후기·수치가 없으므로 후기/지표 섹션은 만들지 않았다. 연구 결과가 생기면 SPEC-006 개정 후 추가한다.
- 사진 대신 HTML/SVG로 만든 앱 목업을 사용했다. 실제 스크린샷 교체는 SPEC-006 §7 개선 후보.
