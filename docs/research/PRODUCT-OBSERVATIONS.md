# 기존 제품 실제 관찰 기록

관찰일: 2026-09-23 · 방식: 브라우저 UI 직접 이동 · 제한: 코드/DB/서버 구현은 확인하지 않음

## Hypora

[실제 앱](https://hypora-2026.vercel.app/)

관찰 경로: 랜딩 → 실행 시작하기 → 빈 프로젝트 목록 → 새 프로젝트 → 이름 입력 → 아이디어 첫 답변 → 다음 질문 → 테스트 메뉴.

- 가입 없이 프로젝트 진입이 가능했다. 새 프로젝트에는 이름 필수·설명 선택 입력이 있었다.
- `Vencubator UX 조사용 샘플`이라는 테스트 프로젝트를 만들고 공개 가능한 가상 아이디어 한 문장을 입력했다. 기존 사용자 프로젝트는 수정하지 않았다.
- 프로젝트 메뉴는 아이디어 / 첫 버전 / 테스트 / 리스크 선택 / 개요였다.
- 질문을 하나씩 보여주고 직접 입력과 제안 선택, 이전·계속 버튼, 진행 표시가 있었다.
- 랜딩에는 AI가 아직 없다는 설명이 있었지만 앱에는 ‘AI에게 아이디어 받기’와 제안 버튼이 있었다. **랜딩 주장과 관찰 UI가 다르다.** 실제 AI 호출 구조는 확인하지 않았다.
- 팀플 서비스라는 답변을 입력한 직후 다음 화면에는 UX 리서치 관련 제안이 나타났다. 일회 관찰로 원인을 단정할 수 없다. Vencubator에서는 Context revision과 생성 제안의 일치 여부를 검증할 필요가 있다.
- 테스트 화면은 아이디어 설명과 첫 버전 계획을 먼저 완료하도록 안내했다. 실제 검증 생성·완료 전체 플로우는 이번 조사에서 실행하지 않았다.
- 랜딩은 ‘내 생각’과 ‘근거로 뒷받침된 주장’을 구분했다. 사용자 판단을 존중하는 철학을 계승한다.

**계승**: 한 질문 집중, 선택+자유입력, 단계별 저장, 구조와 실행 연결, 가설/근거 구분.

**바꿀 것**: Vencubator에서는 모든 문서 작성 후에만 고객 인터뷰를 시작하게 하지 않는다. 문제·고객 가설이 있으면 작은 검증을 허용한다. Context가 바뀌면 오래된 제안을 폐기하거나 재생성한다.

## Persoracle

[실제 앱](https://persoracle-mvp-v1.vercel.app/)

관찰 경로: 랜딩 → 프로젝트 보기 → 표시된 샘플 프로젝트 → 프로젝트 / 페르소나 / 반응 / 후속 정리 탭.

- 자유로운 설명과 항목별 입력 전환, ‘항목 채우기’, 요약과 미확인 질문을 확인했다.
- 페르소나 카드에는 역할, 성향, 관심사가 표시되고 상세/제거/직접 추가가 있었다.
- 샘플 프로젝트 목록과 상단에 점수 81·페르소나 5개가 표시됐다. 반응 탭은 대기 상태, 후속 정리의 평균 점수는 0이었다. 서로 다른 영역의 점수를 실제 검증 결과라고 해석할 수 없었다.
- 반응 실행 버튼, 후속 질문·인사이트 후보·의사결정 메모 저장 UI를 확인했다.
- ‘이 브라우저에 저장됨’, 초기화 전까지 로컬 보관한다는 안내를 확인했다. 계정 동기화 여부를 추정하지 않는다.
- 크레딧은 초기 랜딩 0, 작업공간에서는 50으로 표시됐다. 새 반응 실행·크레딧 결제·메모 변경은 하지 않았다. AI 피드백 품질과 전체 실행 성공은 미검증이다.

**계승**: 고객 관점 다변화, 미확인 질문, 피드백 비교에서 의사결정 메모로 이어지는 구조.

**바꿀 것**: 합성 반응 점수를 실제 수요나 PMF의 점수처럼 사용하지 않는다. 시뮬레이션은 ‘고객에게 물어볼 질문 후보’로 연결한다. 요약 지표는 동일 revision과 결과 출처를 보여준다.

## Vencubator에서 추가할 것

공통 BusinessContext → 가설 → 학습/행동 → Evidence → Decision → Context revision의 지속 루프, 본캐 지식 이전, 근거 기반 부캐 성장, 후속 행동 알림, Web/Android 계정 동기화.

세 서비스의 개념을 연결하는 제안이며 기존 서비스의 API·데이터 호환성이나 코드 재사용 가능성을 확인한 것은 아니다. 직접 데이터 import와 계정 통합은 MVP 이후 별도 명세 대상이다.
