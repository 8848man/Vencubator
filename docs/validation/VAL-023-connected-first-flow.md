# VAL-023 — 앱 첫 실행 연결·브랜드 자산·모션

2026-10-14 · L08-W05 · AUTH-034 · SPEC-019 r0.6 · SPEC-008 r0.1 · 상태: 자동 검사 통과, 4180 직접 조작 미실행

## 확인한 동작

- `/app/` 또는 `/app/index.html`을 새 데모 사용자가 열고 저장이 정상이라면 `/v3.3/`으로 이동한다. `v33Guide`/`v33Explore` 인계 URL, 기존 사용자·프로젝트·기존 온보딩 완료, 첫 흐름 완료, 앱 저장 오류는 재이동하지 않는다. 완료 표시가 있고 사용자 없는 앱은 기존 온보딩 대신 데모 시작 화면을 보인다.
- 안내 마지막 버튼은 완료 표시를 쓴 후 실제 `/app/` 프로젝트 화면으로 이동한다. 저장 실패 시에도 인계 URL로 나가므로 앱↔안내 반복 이동을 피한다. 앱의 저장 오류 복구 및 S1 데모 경계는 유지한다.
- 기존 앱 `mascot()`·`brand()`의 SVG를 `prototype/assets/`로 추출했다. 앱과 `/v3.3/`이 빌드된 `/app/assets/`의 같은 파일을 사용한다. 캐릭터 영역은 180px(좁은 화면 150px)을 예약하고 15화면 진행 동안 크기 0.7→1.1, 별 1→5개가 된다. 증가 효과는 시각 진행 표시이며 스탯과 무관하다.
- SPEC-008의 260ms 아래→위 진입과 그룹 간 50ms(마지막 150ms) 지연을 적용했다. 같은 질문의 선택 갱신은 진입 클래스를 재적용하지 않고 선택 버튼 포커스를 복원한다. OS 모션 감소 시 이동·성장 전환·반복 반짝임을 끈다.

## 실행 결과

| 명령 | 결과 |
|---|---|
| `node --test prototype/tests/*.test.mjs` | 87/87 통과 (첫 실행 분기 3건 포함) |
| `node --test landing-v3.3/tests/*.test.mjs` | 1/1 통과 |
| `node --test --test-concurrency=1 site/tests/*.test.mjs` | 32/32 통과. 공용 SVG·진입 모듈 배포 경로 확인 |
| `node site/scripts/build.mjs` | `site/dist` 생성 성공 |
| `git diff --check` | 오류 없음 |

기본 병렬 `site` 테스트 첫 실행에서 1건이 일시 실패했고, 단독 `mobile-entry` 및 전체 재실행은 통과했다. 여러 테스트 파일이 같은 `site/dist`를 동시에 지우고 다시 만드는 경쟁 상태로 판단해 파일 간 동시성을 1로 고정해 검증했다. 이는 테스트 실행 방식의 제한이며 제품 동작 실패로 판정하지 않는다.

## SDD 발견성 평가

모션 명세는 README→SPEC-008→`prototype/motion.*`→VAL-005로 빠르게 추적됐다. 캐릭터·로고는 `prototype/app.mjs`의 HTML 문자열 속에만 있었고 `.svg` 파일명 검색은 결과가 없어 발견성이 낮았다. [브랜드 자산 색인](../design/BRAND-ASSETS.md)에 원본·사용 화면·관련 명세를 연결해 이 두 자산의 경로는 개선했다. 전체 디자인 토큰과 새 자산에 대한 중앙 등록 절차는 아직 없다.

## 미실행·경계

4180 브라우저 직접 조작과 실기기 320/390px 육안 검사는 이전 작업에서 발생한 브라우저 보안 정책 제한으로 미실행했다. 같은 결과를 얻기 위한 우회 접근은 시도하지 않았다. 정적 빌드와 자동 검사만 성공을 확인했으며, 현재 4180 서버가 새 빌드를 제공하는지·시각적 레이아웃·터치 감각은 사용자 체험으로 확인해야 한다. 실제 로그인, 모바일 네이티브 저장소, AI 개인화, 서버 기록, 운영 배포는 구현·검증하지 않았다.
