# ADR-006 — 피드백 저장소: Cloud Firestore(생성 전용) + 로컬 보관함

2026-09-27 · AUTH-022 · SPEC-015 r0.1 · 상태: 제안(DR-FB-03 사용자 확인 후 확정)

## 맥락
SPEC-015는 자유 의견(최대 1000자), 칩, 점수를 모으고 같은 브라우저의 응답을 슬롯 순서대로 이어 **효용 곡선**을 봐야 한다. S1은 로그인·서버가 없는 정적 사이트(Vercel)이며 프로젝트 데이터는 localStorage에만 있다. ADR-004는 분석(GA4)과 사업 데이터 저장을 분리했고, Firestore 자체 이벤트 저장은 “쿼리·보안 운영 부담”으로 보류했다.

## 선택지
| 안 | 장점 | 한계 |
|---|---|---|
| A. GA4만 (기존 gtag) | 추가 설치 없음, 퍼널·평균 보고서 | 자유 입력 저장 불가(개인정보 정책·매개변수 100자), 응답 단위 원본·개인 내 곡선 조회 어려움, 수집 지연 |
| **B. Firestore 생성 전용 컬렉션** | 같은 Firebase 프로젝트, 무료 한도(일 쓰기 2만) 충분, 응답 원본·자유 입력 보관, 규칙으로 필드 검증, 콘솔·내보내기 | 공개 쓰기 경로의 스팸 위험(규칙 검증 + 후속 App Check), 콘솔 준비 필요 |
| C. Vercel Function + 외부 DB | 서버 검증·속도 제한 | 새 서비스·계정·비밀키 운영, S1 범위 대비 과함 |
| D. Google Forms/Sheets | 즉시 사용 | 앱 흐름 밖으로 나감(요구와 충돌) |

## 결정
- **B를 원본 저장소**로 쓰고, GA4에는 점수·표시·건너뜀 같은 **집계용 열거값만** 보낸다(SPEC-015 §7). 두 저장소를 서로의 백업으로 쓰지 않는다.
- 번들러 없는 정적 빌드를 유지하기 위해 Firebase SDK 대신 **Firestore REST `createDocument`**(웹 API 키 + 보안 규칙)로 전송한다. App Check를 도입할 때(DR-FB-04) 필요한 모듈만 추가 검토한다. gtag와 Analytics SDK 중복 설치 금지(ADR-004)는 유지.
- 보안 규칙: `feedback/{id}`에 `create`만 허용, 허용 필드·타입·길이·열거값 검증, `read/update/delete` 거부. 클라이언트 생성 문서 ID로 재시도 중복을 막는다(이미 존재하면 성공으로 처리).
- 로컬 `vencubator.feedback.v1`이 스케줄 상태와 전송 대기함을 가진다. 프로젝트 저장소와 분리하며 사업 원장·AI context의 출처가 아니다.
- 식별: 피드백 전용 무작위 `respondent`만 사용. GA 클라이언트 ID·프로젝트 ID와 연결하지 않는다. 기기 간 연결 없음.
- 운영 호스트에서만 전송(SPEC-011 호스트 규칙 재사용). 설정값이 없으면 어댑터는 비활성이고 로컬 보관만 한다.

## 결과·후속
- 사용자 작업: Firestore 데이터베이스 생성(위치는 생성 후 변경 불가, 권장 asia-northeast3), `firestore.rules` 배포, 웹 앱 설정값 제공.
- 조회: S1은 Firebase 콘솔. 효용 곡선 내보내기·조회 도구는 관리자 자격 증명이 필요하므로 후속 W(P08-W05)에서 분리한다.
- MVP에서 인증이 생기면 respondent를 계정과 연결할지 별도 ADR로 결정한다.
