# 구현 로드맵 — 프로토타입 → MVP → 고도화

Revision 0.1 · 기준선 planning-v0.2 · 상태: 단계 순서는 사용자 지정, 세부 범위는 검토용 · 실제 구현 미착수

## 단계별 제품 계약

| 단계 | 검증할 질문 | 제공하는 결과 | 데이터/AI/플랫폼 | 종료 조건 |
|---|---|---|---|---|
| S1 프로토타입 | 사용자가 질문→학습→행동→성장을 이해하는가? | 대표 시나리오를 직접 조작하는 Web 데모 | 가상 계정·샘플 근거·결정형 AI 대역, 로컬 저장; 반응형 Web | G-P: 핵심 흐름·중단 복구·성장 의미 확인 |
| S2 MVP | 실제 아이디어에서 근거와 결정을 반복해서 남기는가? | 계정 기반 Web 베타와 Android 테스트 앱 | 실제 인증·DB·서버 정책·AI 공급자 1개·푸시·최소 검수 콘텐츠 | G-M: 기술 무결성 및 4주 파일럿 결과로 다음 결정 |
| S3 고도화 | 어느 개선이 실제 행동·학습·지속 사용을 늘리는가? | 근거로 선택한 개선을 작은 릴리스로 제공 | 안정화→개인화→선택적 연결→선택적 수익화 | G-E: 선택한 개선마다 기준선 대비 효과/운영 건전성 판단 |

MVP와 고도화의 제품 규칙은 SPEC-001~003, 프로토타입 대체 동작은 [SPEC-004](../specs/SPEC-004-prototype.md)가 권위다. 로드맵은 순서·의존성·단계 범위의 권위 문서다. 기술 선택은 ADR-001/002를 따른다.

## 일정 해석

기존 12주 목표를 유지하는 제안: 주 1~2 S1, 주 3~12 S2, S3는 MVP 결과 뒤 별도 추정한다. 주 3 M01, 주 4 M02, 주 5~6 M03, 주 7 M04, 주 8 M05, 주 9~12 M06. 일정은 통과 기준을 대체하지 않는다. 모집/검수/플랫폼 검증이 늦으면 파일럿 관찰 기간을 축소해 완료 처리하지 않고 일정을 갱신한다.

프로토타입 사용자 연구는 합의된 참여자 대상으로만 수행한다. 일정 계획 자체가 외부 연락·초대·결제·공개 배포 권한은 아니다. 기술 개발 내부 작업은 승인된 Stage/Phase 범위 내에서 매 작업마다 재승인을 요구하지 않는다.

## 진행 관리 계층

**Stage → Phase → Work Item(W) → Checkpoint(CP)**.

- Stage: 제품의 성숙도와 출시 범위.
- Phase: 사용자 결과와 검증 묶음. 하나 이상의 세션이 걸릴 수 있다.
- W: 산출물·검증·재개 지점을 지정한 작업. 한 번에 하나만 active. 예상 30~90분을 넘거나 한 번의 제한된 문맥으로 검토하기 어렵다면 착수 전 더 작은 W로 분할한다.
- CP: 작업 상태의 저장 지점. W가 끝나지 않아도 만든다. CP 생성은 W 완료를 뜻하지 않는다.

현재 상태의 단일 권위는 [STATE.json](../execution/STATE.json), 사용 규칙은 [CHECKPOINT-PROTOCOL](../execution/CHECKPOINT-PROTOCOL.md)이다. 단계별 계획에는 실시간 완료 체크박스를 중복 유지하지 않는다.

## Stage 전환 게이트

| Gate | 필수 제출물 | 판단 |
|---|---|---|
| G-P | P01~P04 validation, 가짜/실제 차이 목록, 재사용/폐기 목록, 사용자 이해 문제 | 통과하면 MVP 범위 확정. 연구 미실행이면 기술 데모 완료와 분리하여 blocked |
| G-M | 필수 기술 AC 전체, 실제 4주 코호트 결과, 운영 비용·오류, 미해결 이슈 | 무결성 미충족은 중단/수정. 행동 가설 실패는 확대 대신 해당 Phase 재진입 또는 문제 재정의 |
| G-E | 개선별 가설·변경·비교 결과·롤백·운영 관측 | 효과 확인 시 확대, 무효면 수정/철회. 모든 후보 기능을 만들어야 끝나는 단계가 아님 |

`gate=evaluated`와 `passed`는 구분한다. 파일럿 분석 작업이 끝나도 제품 가설은 실패할 수 있다. 연구 결과·실패 판정은 보존하고 별도 rework W로 처리한다.

## 재사용과 MVP 승격

프로토타입에서 UI 컴포넌트·도메인 이름·샘플 fixture·정책 테스트를 재사용 후보로 둔다. 가상 인증·클라이언트 권한·샘플 실적·로컬 단독 저장은 MVP에서 교체한다. 프로토타입을 단순 배포 설정 변경으로 MVP라고 부르지 않는다. 가상 데이터는 실사용 DB로 자동 이전하지 않는다.

각 Stage에서 사용자 판단권, 시뮬레이션 출처, 본캐/부캐 분리, 중복 보상 방지라는 제품 의미는 유지한다. 구현 품질과 실제 연동 범위를 단계적으로 늘린다.
