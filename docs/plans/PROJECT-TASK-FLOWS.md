# 부캐·태스크 흐름 개선 계획

2026-09-27 · 기획 초안 · 구현 승인/착수 아님

사용자 추가 요구: ‘지금 할 일’은 실제로 해야 하는 작업을 모으고, 학습 길처럼 여러 단계가 하나의 흐름을 이루며 이탈 후 해당 작업을 재개할 수 있어야 한다.

## 1. 태스크의 단위

태스크는 완료할 목적과 산출물이 있는 **재개 가능한 작업 흐름**이다. 퀴즈 한 문항·화면 클릭·알림 각각을 태스크로 생성하지 않는다. 학습 길은 경로/커리큘럼이고, 그 안에서 하나의 목적을 완수하는 학습·실행 묶음을 태스크로 연결한다.

예: ‘고객의 실제 불편 확인하기’ = 개념 배우기 → 답·이유 고르기 → 내 프로젝트 질문 준비 → 현장 실행 → 결과 기록·회고. 학습 완료는 중간 마일스톤, 전체 태스크 완료와 구분한다. 현장 대기 때문에 다음 학습을 막지 않는다. 짧은 학습 전용 흐름이나 운영/조사 흐름도 같은 태스크 인터페이스로 관리한다.

이미 존재하는 learningRuns / learningArtifacts / fieldTasks / evidence / decisions는 ID로 연결한다. 태스크용 진도·답안 사본을 별도 생성하지 않는다. 기존 기록 이관/참조 규칙은 구현 전 데이터 계약에서 정의한다.

## 2. 지금 할 일 UX

- 프로젝트 관련 화면의 ‘지금 할 일’ 플로팅 버튼 → 현재 프로젝트 작업 목록 시트. 학습 문제 중에는 버튼 숨김.
- 상단 ‘이어서 할 일’ 1개: 마지막 저장 단계, 다음 구체적 행동, 남은 시간 추정. 다른 진행 작업은 아래에 노출.
- ‘새로 시작할 일’과 ‘외부 결과 기다리는 일’을 구분. 현재 프로젝트명 명시, 다른 프로젝트와 암묵적 혼합 금지.
- 카드: 목적, 관련 부캐 스탯, 현재 단계, 진행 막대, 중요도/이유, 예상 소요, 목표일, CTA ‘이어서 하기’ 또는 ‘시작하기’.
- 진행 막대는 완료한 작업 단계 수이며 사업 성공률/스탯 점수가 아니다. 선택 단계·건너뛴 단계·완료를 구별하며 분모와 의미를 표시한다.
- 카드 선택 → 목록 시트를 닫고 작업 전용 화면으로 이동. 다이얼로그 중첩 금지. 간단한 힌트/결과는 SPEC-012 정책 사용.
- 학습 길에서 시작해도 같은 태스크 생성/재사용. ‘지금 할 일’에서 열어도 같은 learningRun으로 복귀. 두 진입점에서 중복 작업을 만들지 않는다.
- 추천 1개는 진행 중 작업의 재개를 우선하되 마감/선행 조건 충돌 시 이유를 제시. 추천순 내부에서는 실행 가능 여부 → 중요한 불확실성 → 목표일 → 소요시간. 사용자에게 마감순/짧은 시간순 보조 선택 제공.

## 3. 저장·재개 계약 초안

Task: id, projectId, scopeVersion, flowType, flowVersion, objective, relatedVentureStats, relatedCompetencies, status, priority/reason, dueAt, estimatedMinutes, steps, currentStepId, lastSavedAt, linkedEntityIds.
Step: 안정적인 id/type, 상태, 선행 조건, 산출물 참조, 완료 시각. URL 하나만 저장하는 방식은 피한다. 프로젝트·흐름 버전·단계 ID로 재개 위치를 결정한다.

- 상태: 미시작 → 진행 중 → 외부 대기/보류 → 완료. 의도적 취소는 별도. 탭 닫기/앱 이탈은 완료·취소가 아니다.
- 선택/입력은 기존 초안 저장 규칙으로 유지, 단계 전환은 저장 성공 후 확정. 저장 실패는 ‘저장되지 않음’을 표시하고 마지막 저장 지점을 안내한다.
- 재개 시 마지막 저장한 미완료 단계로 돌아간다. 제출된 문항이면 해설/다음 단계로 복귀하며 재채점하지 않는다.
- 각 단계 완료와 보상 지급은 중복 실행해도 한 번만 적용. 같은 목적/학습 회차에 새 태스크를 중복 생성하지 않는다. 반복 실험은 명시적 새 회차.
- 가설 범위가 바뀌면 이전 근거를 현재 완료로 자동 인정하지 않는다. 기존 기록은 보존하고 적용 여부를 다시 확인한다.
- 흐름 버전 변경 시 단계 매핑 또는 사용자 안내로 복구. 없는 단계로 조용히 이동하거나 초안을 삭제하지 않는다.
- 프로토타입은 같은 브라우저·출처에서만 재개. MVP에서 인증된 사용자/프로젝트 권한과 서버 저장, 기기 간 충돌 해결을 추가한다.

## 4. 부캐·본캐 연결 (제안 유지)

부캐 후보 6축: 문제의 중요성 / 해결의 효과 / 시장의 가능성 / 고객을 만나는 힘 / 수익의 지속성 / 약속을 지키는 힘. 육각형은 근거의 지지 상태, 작업 진행률은 별도로 표시. 미확인을 낮은 평가와 구분. 평가 척도는 후속 SPEC-002 개정 전 확정하지 않는다.

태스크 실행 결과·회고로 본캐 역량을 평가하고, 확인된 본캐 역량으로 설명/질문 지원 수준을 조절한다. 점수끼리 자동 전이하지 않는다. 본캐가 높아도 부캐 근거를 생략하지 않는다. 태스크 완료 자체는 본캐 숙달/부캐 사업성의 증거가 아니다.

## 5. 단계별 적용 계획

1. 명세: SPEC-002/003/005 및 ARCHITECTURE 개정안 작성. 기존 7축 데이터와 부캐 6축 전환, 태스크 참조 관계·재개·중복 방지·완료 조건 확정.
2. 프로토타입: 고객 이해 흐름 1개로 양쪽 진입점/같은 진도/이탈 복원 검증 후 다른 흐름 확대. 프로젝트 상세 육각형·목록 시트 연결. AI 평가를 실제 기능으로 가장하지 않음.
3. MVP: 계정 기반 저장, 기기 간 재개, 실행 대기/알림 연결, 제한된 역량 평가 및 질문 분기.
4. 고도화: AI 개인화, 적응형 태스크 추천, 역량 전이 검증. 중단 복원은 고도화까지 미루지 않는다.

## 6. 필수 검증 시나리오

- 답 선택/이유 선택/응용 초안 도중 이탈 후 같은 프로젝트의 같은 단계·선택 복원.
- 학습 길→시작→이탈→지금 할 일→재개, 반대 진입도 동일 작업.
- 학습은 끝났으나 현장 실행 대기이면 학습 완료/태스크 대기를 구분.
- 저장 실패·연속 클릭·새로고침으로 진도/보상이 중복되지 않음.
- 프로젝트 전환·가설 범위 변경·흐름 버전 변경에서 기록 혼합/손실 방지.
- 진행 중 작업 여러 개여도 추천 행동 하나가 명확하고 외부 대기로 학습 전체가 막히지 않음.
