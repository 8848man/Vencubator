# S3 — 고도화 구현 명세·계획

Revision 0.1 · Candidate / 미착수 · 기간: MVP 결과 후 선택 범위별 추정

목적: 확인된 병목을 개선한다. 고도화는 기능 수를 늘리는 고정 패키지가 아니다. 각 Phase 착수 시 실측 기준선·가설·대상·필수 기능·비목표·AC·계측·롤백을 새 Spec revision으로 확정한다. 아래 계획만으로 결제·외부 연결·공개 출시를 구현 승인한 것으로 간주하지 않는다.

## E01 — 안정성·성능·운영 비용

- 진입: G-M evaluated, 기술/제품 판정 읽기, 해당 개선 선택. 핵심 가치 가설 실패라면 기능 확장보다 MVP 수정이 먼저.
- 범위: 실제 오류·지연·AI 비용 상위 병목, 지원/복원 경로. 근거 없이 인프라를 분산하지 않음.
- 산출물: 운영 기준선·개선 Spec/ADR·전후 검증·릴리스.

| W ID | 작업·완료 결과 | 검증/증거 |
|---|---|---|
| E01-W01 | 오류·응답·비용·문의 기준선과 가장 중요한 개선 1개 선정 | 측정 기간/분모, 목표·악화 방지 지표를 구현 전에 고정 |
| E01-W02 | 선정 병목 수정과 migration/호환 영향 검증 | 관련 회귀·부하 또는 실패 재현, rollback |
| E01-W03 | 제한 배포 후 관찰·전후 판단 | 오류/지연/비용 비교, 데이터 손실·중복 0건 |

- 종료: 정한 개선 목표 충족 또는 철회 이유 기록. 결과 불충분이면 확대하지 않음.
- 재개: 관측 기간·배포 revision·변경된 설정과 측정 결과. 미리 정하지 않은 목표를 사후 성공 기준으로 쓰지 않음.

## E02 — 개인화와 학습 전이

- 진입: E01 passed, 재방문·적용의 구체 병목 확인, 사용자가 선택한 범위.
- 범위: 개념 숙달 기반 설명 생략, 지연 복습, 업종/단계별 과제 난이도, 추천 이유 개선. 점수 공식 변경은 별도 영향 분석.
- 산출물: 한 개인화 가설의 Spec·평가셋·실험·결정.

| W ID | 작업·완료 결과 | 검증/증거 |
|---|---|---|
| E02-W01 | 한 대상과 병목, 비교 설계·숙달 평가 rubric 결정 | 기존 추천 기준선·표본/관찰창·주요 지표 고정 |
| E02-W02 | 한 개인화 기능 구현, 검수 콘텐츠·추천 설명·fallback | 프로젝트 간 근거 오승계 방지, 보상 회귀, 미학습자 경로 |
| E02-W03 | 실제 행동/적용 변화와 피로 평가, 유지/철회 | 클릭률만이 아닌 학습 전이·행동 지표 |

- 종료: 실험 결과로 범위 확대 여부 결정. 통계적 근거가 부족하면 탐색 결과로 남김.
- 재개: 대상/실험 배정·정책 revision 보존, 중간 중단 시 관찰기간과 누락 표본 기록.

## E03 — Hypora·Persoracle 및 근거 도구 연결

- 진입: E01 passed, 실제 import/연결 수요 및 인터페이스 확인. E02 완료는 필수 아님.
- 범위: 선택한 연결 한 개부터. Context 수동 export/import 또는 문서화된 API, 출처·중복·개인정보·충돌 처리. 기존 앱 API가 있다고 가정하지 않음.
- 산출물: 연결 계약 Spec/ADR, 변환 preview, 호환 fixture, 되돌리기 정책.

| W ID | 작업·완료 결과 | 검증/증거 |
|---|---|---|
| E03-W01 | 대상 포맷/권한/필드·가설·근거 mapping과 수요 확인 | 샘플 계약, 미지원 필드와 사용자 확인 경계 |
| E03-W02 | 한 연결의 preview→사용자 확인→versioned import | 중복 import·기존 값 충돌·부분 실패·취소 |
| E03-W03 | 제한 사용자 검증·출처 재현·이탈/가치 판단 | AI 시뮬레이션을 실제 Evidence로 승격하지 않는 테스트 |

- 종료: 확인된 인터페이스에서 데이터 의미가 보존되고 연결의 행동 가치를 평가함. 연결 수요가 없으면 deferred.
- 재개: import job ID·입력 hash·확정 여부·수정된 revision. 결과 불명확하면 기존 job 결과 확인 전 재적용 금지.

## E04 — 수익화와 공개 출시 확대

- 진입: E01 passed, 반복 가치/지불 실험 근거, 예산·서비스 정책·플랫폼 출시 조건 확인. E02/E03은 독립 선택.
- 범위: 먼저 가격/가치 실험. 근거가 있으면 선택한 상품 1개의 결제/권한/해지/복구와 공개 출시 범위를 별도 Spec으로 승인. Android/Web 결제 경로와 최신 정책은 착수 시 재확인.
- 산출물: 수익화 판단·필요 시 결제와 출시 Spec/ADR·운영 계획.

| W ID | 작업·완료 결과 | 검증/증거 |
|---|---|---|
| E04-W01 | 유료 가치·가격·제한·결제 채널·성공/중단 기준 정의 | H09 후속 실제 선택 실험, 단순 지불 의향과 구별 |
| E04-W02 | 선택된 경우에만 결제·이용 권한·해지·웹훅·장애 복구 구현 | sandbox 결제·중복·환불/해지/권한 회귀; 실거래와 구분 |
| E04-W03 | 공개 출시 readiness·제한 확대·수익/비용·지원 관찰 | 실제 릴리스 기록, 취소율/문의/마진 등 사전 정의 지표 |

- 종료: 실험 결과와 운영 책임을 근거로 확대/보류 결정. 결제를 선택하지 않으면 W02는 이유와 함께 deferred, passed로 위장하지 않음.
- 재개: 외부 거래/출시 job의 실제 상태를 조회하고 불명확한 작업을 재실행하지 않는다. 자격증명·카드 정보는 CP에 기록 금지.

## 고도화 공통 종료 규칙

선택한 각 개선의 필수 W와 검증이 완료되고 G-E 평가가 있으면 해당 릴리스 묶음을 종료한다. deferred 후보 수를 줄이려고 불필요한 기능을 만들지 않는다. 범위가 늘면 새 Phase/W/Spec과 계획 revision을 추가하고 기존 완료 기록을 보존한다.
