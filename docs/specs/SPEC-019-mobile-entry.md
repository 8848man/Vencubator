## r0.4 — `/v3.3/` 체험과 실제 앱 코치마크

사용자 최신 요청에 따라 `/v3.3/`의 r0.2 랜딩 재사용·모바일 자동 이동 규칙을 **이 체험 경로에 한해 변경**한다. 사이트 `/`의 모바일 `/app/` 직접 이동은 유지한다. `/v3.3/reference/`의 54장 흐름 연구 화면은 그대로 둔다. `/v3.3/`은 화면 폭과 무관하게 1~4구간의 짧은 벤큐베이터 맞춤 튜토리얼·정보 입력을 시작하며, 마지막에는 실제 `/app/`으로 이동해 5구간을 진행한다. 기존 사용자에게 제공하던 v3.1 랜딩은 `/beginner/`에서 계속 볼 수 있다. 이 절이 이전 절의 `/v3.3/` 동작보다 우선한다.

지정 레퍼런스 10번의 핵심은 **실제 제품 화면 위 코치마크**다. 배경 전체를 짙게 가리고 대상 컨트롤만 밝은 테두리·포인터로 강조하며, 인접한 흰 설명 카드에 다음 행동을 적는다. 목표는 그림 속 앱을 조작하는 것처럼 꾸미는 게 아니라 사용자가 실제 첫 프로젝트를 만들게 하는 것이다. 원본의 노란색·브랜드 문구는 복제하지 않고 벤큐베이터의 연두색 강조와 `아이디어 → 배움 → 확인` 언어를 쓴다.

1~4구간은 `한 문장으로 시작` 소개 → 아이디어 단계 → 지금 필요한 도움·오늘의 속도 → 아이디어 문장과 내 시작점 요약으로 구성한다. 질문 응답·아이디어·현재 단계는 `vencubator.v33.draft.v1`에 저장하며 새로고침 후 복구한다. 민감하지 않은 완료 버전·시각은 별도 `vencubator.firstFlow.v1`에만 저장한다. 저장 차단 시 계속 체험할 수 있지만 저장되지 않았음을 알린다. 입력은 URL에 넣지 않는다. 동일 출처의 `/app/`으로 건너갈 때 명시적 시작 행동에서만 초안을 읽어 기존 프로젝트 데이터를 덮어쓰지 않고 새 프로젝트 입력칸에 미리 채운다.

5구간은 실제 앱의 프로젝트 목록 `첫 프로젝트 만들기`(프로젝트가 있으면 `+ 새 프로젝트`) → 새 프로젝트 설명 입력 → `나의 학습 로드맵 시작`을 순서대로 활성화한다. 각 순간 한 대상만 포인터·키보드 활성 상태로 두고, 나머지 화면을 짙게 덮는 wrapper와 짧은 도움말·진행 표시를 둔다. 대상 밖 클릭·Tab 이동·Enter/Space 동작·폼 제출은 막는다. 대상은 실제 DOM이며 정상 앱 핸들러가 실행된다. 입력 실패나 저장 실패 시 코치마크를 끝내거나 완료로 표시하지 않는다. 프로젝트 저장 성공 후 wrapper를 제거해 일반 앱 사용으로 돌아간다. 사용자는 안내를 종료할 수 있고 기존 프로젝트는 항상 보존한다.

이 구현은 **S1 로컬 체험**이다. 실제 카카오·Google·이메일 인증, 서버 계정별 완료 버전, 네이티브 모바일 저장소와 동기화하지 않는다. r0.3의 독립 로그인 게이트는 설계 상태이며 여기서는 `데모로 앱 열기`라고 명시한다. 로컬 완료 표시가 계정 인증 또는 다른 기기의 완료 근거가 되지 않는다.

r0.2 정정: `/v3.3/`은 새로운 디자인의 독립 랜딩이 아니다. 현재 사이트가 사용하는 기존 v3.1 입문 랜딩과 독자 선택 흐름을 그대로 보여 주며, 모바일 폭에서는 그 화면을 건너뛰어 `/app/`으로 이동한다. 마이루틴 레퍼런스 실행 흐름은 별도 `/v3.3/reference/` 인터랙티브 HTML에서 제품 적용과 분리해 체험한다. 2026-10-13 사용자 정정을 승인 근거로 삼는다.

## 목적과 기대 효과

작은 화면에서 홍보용 랜딩을 다시 읽는 단계를 없애고 곧바로 앱의 첫 행동으로 이끈다. 처음 온 사람은 Vencubator가 **아이디어를 한 문장으로 적고 → 필요한 개념을 배우고 → 현실에서 확인하고 → 다음 결정을 남기는** 도구임을 이해한다. 질문은 사용자를 분류하거나 사업 가능성을 채점하기 위한 것이 아니라 첫 화면의 문구와 시작점을 맞추기 위한 것이다. 기대 효과는 첫 프로젝트 시작까지의 경로 단축과 첫 행동의 명확화다. 전환율·완료율 개선은 실제 관찰 전 가설이다.

## 레퍼런스 분석 — 마이루틴 스크린샷 54장

제공 폴더의 파일명 정렬 순서 기준. 01~07은 가치·작동 방식·사회적 증거를 보여주는 소개, 08~18은 말풍선 질문과 큰 선택 카드로 생활 패턴을 묻는 진단, 19~25는 진단 사이에 작동 원리를 설명하는 화면, 26~29는 프로필·요약, 30~34는 첫 행동 전 약속·전후 비교, 35~54는 앱 화면 위 코치마크를 따라 첫 루틴을 실제로 만드는 실습이다. 진행 표시, 뒤로가기, 하단 고정 주 행동, 선택 전 비활성 상태가 일관되게 보인다.

차용할 구조: `짧은 약속 → 한 번에 한 질문 → 내 답에 맞는 요약 → 앱 안에서 첫 행동`. 사용자의 선택이 다음 문구에 반영되고, 마지막은 제품의 실제 핵심 동작으로 이어진다. 그대로 옮기지 않을 것: 긴 생활 진단, 연령·수면 시간 수집, 성공률 수치, 루틴 연속 수행 보상, 강제 서명. Vencubator의 근거 상태와 사업 성과를 과장할 위험이 있다. 스크린샷은 한 사용자 세션의 화면 관찰이며 마이루틴의 전체 기능·성과 증거가 아니다.

1. **직접 진입:** 사이트 `/` 또는 `/v3.3/`을 600px 이하에서 열면 `/app/`으로 `location.replace`한다. `/beginner/`, `/value/`, `/test/`, `/v3.3/reference/` 직접 URL은 레퍼런스·독자 경로 확인을 위해 유지한다. 쿼리 중 내부 계측 플래그는 기존 허용 목록만 전달한다. 데스크톱 `/`와 `/v3.3/`은 동일한 기존 랜딩·독자 선택 흐름을 보여 준다.
2. **환영/짧은 튜토리얼:** `내 생각 → 작은 학습 → 실제 확인`의 관계를 설명한다. 체험판, 브라우저 로컬 저장, 가상 예시를 초기 화면에서 밝힌다. 건너뛰기와 뒤로가기를 제공한다.
3. **맞춤 질문:** 아이디어 단계(한 문장 있음/떠오르는 중/아직 없음), 지금 필요한 도움(누구의 문제인지/무엇을 물을지/다음 행동), 오늘 쓸 시간(5분/10분/천천히)을 한 화면에 하나씩 선택한다. 모두 자기 보고 값이다. 나이·성별·매출·투자 단계는 묻지 않는다.
4. **아이디어 문장:** 선택 입력이며 건너뛰면 빈 프로젝트 시작 화면에서 나중에 적을 수 있다. 자유 입력은 120자 제한, HTML 이스케이프, 로컬 저장만 한다.
5. **맞춤 요약:** 답변에 맞는 첫 제안 하나를 보여준다. 추천은 판단 결과가 아니며 수정 가능하다. 시작하면 기존 앱의 이름 입력·새 프로젝트 생성·학습 로드맵으로 연결한다. 마친 뒤에는 최초 튜토리얼을 반복하지 않는다. 진행 중 새로고침 시 현재 단계와 답변을 복구한다.

## 설계 원칙

- **작은 행동 하나:** 모든 화면의 주 행동은 하나. 선택지는 44px 이상, 진행도는 `n/5` 텍스트와 시각 막대를 함께 사용한다.
- **질문마다 이유:** 사업 정보가 아니라 추천 시작점을 맞추기 위한 질문임을 설명한다. `아직 모르겠어요`와 건너뛰기를 정상 경로로 둔다.
- **실제 앱으로 끝내기:** 완료 애니메이션만 보여주지 않고 기존 프로젝트 만들기와 학습 로드맵을 직접 사용한다. 샘플은 가상임을 표시한다.
- **판단권은 사용자에게:** 상태·시간을 능력 등급이나 확정 사실로 변환하지 않는다. AI/시뮬레이션/실제 고객 관찰을 섞지 않는다.
- **재방문 존중:** 저장한 앱 상태가 있으면 온보딩보다 그 상태가 우선한다. URL 강제 미리보기는 실제 데이터를 덮어쓰지 않는다.
- **접근성과 안정성:** 320px 단일 열, 키보드·뒤로가기·초점·`prefers-reduced-motion`·safe area, 저장 실패 시 안내와 계속 이용 경로를 제공한다.

## 랜딩 v3.3과 레퍼런스 체험의 역할

`/v3.3/`은 기존 사이트의 v3.1 입문 랜딩·독자 선택 화면을 재사용한다. 데스크톱에서는 기존 내용과 인터랙션을 유지하고, 모바일 폭에서는 앱으로 직접 이동한다. 별도 `/v3.3/reference/`는 마이루틴 스크린샷 54장의 **화면 전개 구조**와 주요 인터랙션을 벤큐베이터 문구·개념으로 번안한 검토용 HTML이다. 가치 약속, 단계별 질문, 답에 따른 요약, 앱 내부 첫 프로젝트 생성·학습·고객 확인 코치마크를 화면에서 조작한다. 원본의 생활 루틴·연령 질문·보상 수치를 제품 요구로 옮기지 않는다. 레퍼런스 체험 답변은 저장하거나 Vencubator 앱에 인계하지 않는다. 원본 앱 화면·상표·성과 수치의 복제물이 아니라 제공 스크린샷을 해석한 흐름 시뮬레이션임을 표시한다.

프로토타입 로컬 저장만 사용한다. 실제 회원 프로필·서버 동기화·알림·AI 추천은 구현하지 않는다. `600px`은 이 작업의 반응형 분기 규격이며 기기 종류 판정이 아니다. 실험 계측, 운영 배포, 사용자 연구는 별도 작업으로 남긴다.

## r0.3 목표 — 첫 흐름 완료 표시와 로그인 게이트

### 목적·범위

첫 1~4구간은 앱에 들어가기 전 `가치 이해 → 아이디어 단계·필요한 도움 → 내 시작점 요약`으로 압축한다. 레퍼런스 HTML의 1~4구간은 34개 화면으로 흐름 분석 도구이며, 실제 출시 흐름의 화면 수가 아니다. 목표는 **소개 1장, 질문 2~3장, 요약 1장**이다. 요약에서 `내 프로젝트 시작하기`를 누르면 로그인/가입 화면을 연다. 로그인 후 5구간은 가짜 앱 모형 대신 실제 앱에서 첫 프로젝트를 만드는 안내가 된다. 정확한 화면 수·문구는 사용성 관찰로 조정한다.

첫 흐름 완료 표시는 인증 자격이 아닌 버전이 있는 **기기별 UX 선호**다. 명칭은 `firstFlowCompletedVersion`으로 하며, 액세스 토큰·JWT·세션 ID와 혼동되는 `first flow token`을 제품·코드 용어로 쓰지 않는다. 로그인 상태는 별도의 검증된 세션에서 얻는다. 브라우저의 모바일 폭과 모바일 브라우저는 같은 origin의 브라우저 저장소를 쓴다. 네이티브 모바일 앱 저장은 후속 구현 경계다([ADR-007](../adr/ADR-007-first-flow-auth-state.md)).

### 진입 판단 순서

라우터는 세션 판정이 끝나기 전 로그인/첫 흐름을 잠깐 보여 줬다가 바꾸지 않는다. `auth=checking` 동안 중립적인 로딩 화면을 둔다. 판정이 끝나면 다음 표를 적용한다. 로그인한 계정의 완료 버전이 기기 표시보다 우선한다.

| 검증된 인증 | 계정 완료 버전 | 기기 완료 버전 | 첫 화면 | 다음 행동 |
|---|---|---|---|---|
| 로그아웃 | 해당 없음 | 현재 버전 미만/없음 | 압축한 첫 흐름 1~4 | 완료 또는 건너뛰기 → 로그인 게이트 |
| 로그아웃 | 해당 없음 | 현재 버전 이상 | **독립 로그인 게이트** | 로그인 성공 → 계정 상태에 따라 앱/첫 흐름 |
| 로그인 | 현재 버전 미만/없음 | 무관 | 압축한 첫 흐름 1~4 | 완료 → 계정 버전 기록 → 실제 앱 첫 프로젝트 |
| 로그인 | 현재 버전 이상 | 무관 | 저장된 앱 화면 | 홈/진행 중 프로젝트 복원 |

같은 브라우저에서 첫 흐름을 방금 마치고 인증에 성공한 경우, 서버가 확인한 **그 계정**에만 완료 버전을 기록한 뒤 앱으로 보낸다. 과거 기기 표시만으로 다른 계정의 완료 상태를 자동 변경하지 않는다. 기존 계정의 완료 버전이 낮다면 계정 기준 첫 흐름을 보여 주되 `이미 내용을 알아요` 건너뛰기를 제공한다. 계정별 데이터는 로그인 전에 노출하지 않는다.

```mermaid
flowchart TD
  A[/app/ 진입] --> B{세션 확인 완료?}
  B -->|아니오| Z[중립 로딩/오류·재시도]
  B -->|로그인됨| C{계정 첫 흐름 완료?}
  B -->|로그아웃| D{기기 첫 흐름 완료?}
  C -->|예| H[저장된 앱 화면]
  C -->|아니오| F[압축한 1~4구간]
  D -->|예| L[로그인 게이트]
  D -->|아니오| F
  F -->|로그아웃 상태 완료/건너뜀| L
  F -->|로그인 상태 완료/건너뜀| H
  L -->|성공| C
  L -->|취소/실패| L
```

### 별도 로그인 게이트 화면

헤드라인은 `이제 내 프로젝트를 이어가요`, 설명은 `로그인하면 내가 만든 프로젝트와 다음 배움을 저장하고 다시 열 수 있어요`를 기본안으로 둔다. 실제 계정 동기화 전 프로토타입은 이 약속을 표시하지 않고 `로그인 흐름 미리보기`로 명시한다.

1. 주 행동: `카카오로 계속하기`, `Google로 계속하기`, `이메일로 계속하기`를 독립 버튼으로 제공한다. 제공 순서는 대상 사용자 조사 후 확정하고, 특정 제공자를 강제하지 않는다. Google 버튼은 Google Identity Services의 공식 렌더링 규칙을 따른다.
2. 이메일 경로 기본안: 이메일 입력 → 일회용 코드 수신·입력 → 성공. 새 계정과 기존 계정은 같은 입력 경로를 사용한다. 비밀번호 방식 채택 여부, 발송 인프라·코드 만료·재전송 제한은 실제 인증 구현 Spec/ADR에서 확정한다.
3. 보조 행동: `처음 안내 다시 보기`, `로그인 도움받기`. 첫 흐름을 되돌아봐도 기존 완료 표시는 삭제하지 않는다. 로그인 취소나 제공자 오류 뒤에는 같은 게이트로 돌아오고 선택한 방식·오류 원인·재시도 행동을 보여 준다.
4. 로그아웃 후 앱을 다시 열면 첫 흐름을 반복하지 않고 이 게이트로 온다. 세션 만료 중 작성하던 내용은 가능한 범위에서 보존하되 서버 기록이 완료됐다고 표시하지 않는다. 다른 계정으로 로그인하면 이전 계정의 프로젝트·답변을 가져오지 않는다.
5. 기기 저장이 지워졌거나 차단된 사용자는 첫 흐름을 볼 수 있다. 첫 화면에 `이미 계정이 있어요 · 로그인`을 항상 제공해 재방문자가 강제로 1~4구간을 반복하지 않게 한다.

### 완료 표시 기록과 답변 경계

- 완료 표시는 1~4구간 요약을 확인하거나 명시적으로 건너뛴 순간에만 기록한다. 화면을 열거나 질문 하나를 고른 것만으로 완료 처리하지 않는다. `completedVersion`과 `completedAt`만 저장하며 아이디어·질문 답변·이메일·제공자 정보는 넣지 않는다.
- 진행 중 답변은 별도 임시 초안이다. 로그인 성공 전에는 계정 근거로 간주하지 않는다. 인증 후 사용자가 미리 채운 아이디어 문장을 확인해야 해당 계정 프로젝트 초안으로 옮길 수 있다. 다른 계정으로 로그인하거나 취소하면 자동 이전하지 않는다.
- 마이너 문구 수정은 완료 버전을 올리지 않는다. 필수 행동이 바뀐 메이저 흐름에서만 버전을 올리고, 복귀 사용자에게 전체 1~4구간 대신 변경된 안내만 보여 주는 방안을 먼저 검토한다.
- 기기 완료 표시는 로그아웃 때 유지한다. 명시적 `처음 안내 다시 보기`는 표시만 다시 보여 주며 인증·계정 데이터는 바꾸지 않는다. 브라우저 데이터 삭제·사생활 보호 모드·새 기기에서는 표시가 없을 수 있으므로 완료 표시는 개인 식별이나 접근 권한의 증거가 아니다.
