# SPEC-004 — 가상 데이터로 검증하는 프로토타입

Revision 0.1 · Approved for S1 · AUTH-003 · Related R15/R16, SPEC-002/003

## Intent / Scope / Non-goals

실제 인프라 투자 전에 질문→아이디어 요약→학습/행동→성장 흐름을 조작 가능한 Web에서 검증한다. Screen 01~13을 대표 시나리오로 연결한다. 로그인은 데모 진입이며 실제 인증이 아니다. 가상 fixture와 결정형 AI 대역, 로컬 draft/confirmed 저장을 사용한다. 실제 계정·운영 데이터·AI 추론 품질·푸시·Android 출시·결제는 제외한다.

## User Flow / Functional Requirements

가상 로그인→프로젝트 만들기→4~6개 질문→사용자 요약 확인→부캐→학습→가상 관찰·판단→보상→다음 행동. 새로고침으로 저장 지점 복구. 정상, 오답과 복습, 가설 반박, 중단 복구 네 시나리오 제공.

## Data / API Requirements

동일한 Domain 명칭과 SPEC-002 규칙을 사용하되 adapter는 로컬 저장/fake AI다. mock은 앱 화면과 개발 설명에 명시한다. fixture에는 실제 고객 개인정보를 사용하지 않는다. 저장 schemaVersion, 입력 draft, confirmed revision, sourceActionId를 포함한다. 서비스 경계를 통해 호출해 MVP에서 실제 adapter로 교체할 수 있도록 하되 일반화 프레임워크를 과도하게 만들지 않는다.

## UI/UX / Error Cases

‘프로토타입 · 가상 데이터’ 안내, 실제/시뮬레이션 근거 구분, 본캐/부캐 변화 구분, 모션 감소. AI 대역 지연·오류·저장 실패는 시나리오로 재현할 수 있게 한다. 저장소 용량/차단 시 초안 복구 한계와 재시도를 표시한다. 데모 초기화는 해당 데모 namespace만 대상으로 하고 기존 사용자 브라우저 데이터를 지우지 않는다.

## Analytics

로컬 이벤트 기록과 관찰용 과제 완료 이력만 사용. production 분석 파이프라인 통과를 주장하지 않는다. 연구 기록은 동의받은 범위와 익명 식별자로 저장한다.

## Acceptance Criteria / Validation

| ID | 기준 | 방법 |
|---|---|---|
| AC-P01 | 첫 진입부터 다음 행동까지 가상 시나리오 전체를 조작 가능 | 브라우저 수동/핵심 E2E |
| AC-P02 | 모름/수정 값이 보존되고 사용자 확인 전 확정 Context가 되지 않음 | 상태 전이 fixture |
| AC-P03 | 퀴즈와 실제 근거의 성장 차이, 반박 상태, 중복 무보상을 구분 | 정책 단위·화면 검증 |
| AC-P04 | Reward 건너뛰기/재생/모션 감소가 데이터 결과를 바꾸지 않음 | 접근성·원장 대역 확인 |
| AC-P05 | 인터뷰 중·확정 직후 새로고침으로 저장 지점을 복구 | 로컬 저장 복원 |
| AC-P06 | 가상 로그인·AI·근거·알림을 실제 운영 결과와 혼동하지 않게 표시 | 화면/네트워크 수동 검사 |

프로토타입에서 AC-P를 통과해도 실제 권한·DB 원자성·다중 기기·푸시의 AC-F/G/U를 통과한 것으로 세지 않는다. S1 검증과 S2 검증 결과를 별도 VAL에 기록한다.

## 2026-09-23 학습 중심 개정 — AUTH-004

진입/홈/학습/적용 흐름은 SPEC-005 r0.1이 우선한다. 한 문장 프로젝트 생성 직후 학습 길에 진입하며, 6문답과 전체 Context 작성은 선행 필수가 아니다. 홈은 다음 학습 한 개를 안내한다. 스탯/근거/결정은 프로젝트 상세에서 확인한다. 개념→문제→내 프로젝트 적용→실행→회고를 연결하며 학습 완료와 현장검증을 분리한다. 기존 데이터 및 SPEC-002 성장 원칙은 유지한다.
