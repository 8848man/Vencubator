# SPEC-013 — 모바일 우선, 재개 가능한 작업

r0.1 · AUTH-017 · 2026-09-27 · 사용자 요청으로 명세·태스크 구현 승인

## 범위와 권위
애플리케이션에서 충분히 조작 가능한 모바일 UX를 기본으로 한다. S1은 반응형 Web이며 네이티브 앱/기기 간 동기화를 구현했다고 표현하지 않는다. 이번은 태스크 구현 + 부캐 6축 구조 명세(ARCHITECTURE 부록), 육각형/자동 평가/새 점수 구현은 제외한다. SPEC-005의 현장 실행 1개 제한은 **새 작업 흐름에서는 여러 개를 보관하고 추천 하나만 표시**로 개정. 이전 API 기본 모드는 호환을 위해 보존한다. SPEC-002 기존 점수 정책은 유지.

## 태스크 계약
- 한 목적의 개념→문제→응용 준비→현장 실행→결과 기록/회고. 학습 완료와 전체 완료 구분. 질문·답안은 learningRuns/uiDraft, 준비물은 learningArtifacts, 현장 실행은 fieldTasks, 결과는 evidence/decisions가 원본이다.
- getProjectTasks(project)는 읽기 전용 projection. TaskMeta는 사용자가 정한 우선순위/목표일/소요시간/대기·보류·취소만 저장한다. completed와 currentStep을 중복 저장하지 않는다.
- 학습 길의 시작과 작업 목록의 시작은 같은 startLesson을 사용. 기존 run을 재사용하며 재개에서 answerLesson/보상은 호출하지 않는다.
- ID는 프로젝트·concept·originScopeVersion(구기록 legacy)·run.createdAt(구기록은 기존 run key 대체)로 안정화. 첫 응용이 가설 범위를 생성해도 동일 작업 ID 유지. 없던 run은 시작 시 한 번 생성.
- 이전 범위와 지원하지 않는 흐름은 기록으로 표시하고 재개 차단. 초안 삭제/자동 점수 이관 없음.
- 현장 초안은 taskId별 분리. 구기록 uiDraft.evidence는 taskId가 같을 때만 승계. 전략은 결과 저장 뒤 별도 의사결정까지 완료해야 전체 완료.
- 기존 앱과 같이 각 상태 전환은 transact 저장 성공 후 화면 이동. 저장 실패는 진도/보상 불변. 다른 탭이 저장 데이터를 바꿨다면 덮어쓰기 차단, 새로고침 안내. 같은 브라우저·origin 재개만 지원.

## UI 계약
- 학습 홈·프로젝트 상세: '지금 할 일' 카드 하나(페이지에서 가장 눈에 띄는 요소: 짙은 녹색 바탕, 제목·현재 단계·예상 시간·단계 수, 주 행동 1개) + '전체 N개 보기'로 목록 진입. 카드·버튼·시트 이름은 모두 '지금 할 일'로 통일(r0.1의 '지금 이어갈 일' 대체). '내 프로젝트'의 프로젝트 선택은 상세로 이동(기존 스탯 표시는 유지, 6축 UI는 미구현).
- 이름 있는 floating button '지금 할 일 N'은 dashboard/details에서만 노출. 목록은 모바일 modal sheet / 데스크톱 중앙 dialog. 선택 시 닫고 전용 작업 상세로 이동. 폼·학습·다이얼로그 중에는 떠 있는 버튼 없음.
- 작업 카드: 제목, 현재 단계, 관련 영역, 다음 행동, 사용자 지정 마감·중요도. 상세: 5단계 목록(건너뜀/완료/대기 명시), 완료 조건·소요시간·중요도 이유·설정.
- 진행 막대는 단계 수 표현일 뿐 시간/성공률 아님. 주 표현은 '질문 준비 중', '학습 완료 · 실행 준비' 등. 다음 행동 소요 시간은 추정으로 표시하고 수정 가능.
- 추천순: 실행 가능한 진행 작업 → 새 학습 → 외부 대기 → 보류 → 완료/취소/이전 범위. 같은 그룹은 중요도 → 목표일 → 소요시간 → ID로 안정 정렬. 마감순·짧은 시간순은 보조. 사용자 선택은 자동으로 변경하지 않음.
- 대기·보류·취소는 기록을 보존하며 재개/다시 열기 가능. 자동 외부 실행 없음. 현장 실행 대기는 다음 학습을 막지 않음.

- 작업 상세의 돌아가기(r0.2, 사용자 발견 버그 수정): 상세는 들어온 화면(`route.from` = 학습 길 | 프로젝트 상세)을 기억하고, 상단 `← 학습 길`/`← 프로젝트 상세`와 하단 돌아가기는 그 화면으로 이동한다. 목록 시트는 별도 `☷ 전체 작업` 버튼으로 연다(r0.1에서는 뒤로 버튼이 시트만 열어 원래 화면으로 돌아갈 수 없었음). 같은 탭에서 상세로 들어온 경우 브라우저·기기 뒤로가기도 들어온 화면으로 돌아가며, 상세에서 작업을 시작한 뒤 뒤로가기도 같은 화면으로 간다. 새로고침 뒤에는 `route.from`으로 앱 안 돌아가기만 보장한다.

## r0.3 — 학습 로드맵·작업 목록 시각화 (AUTH-020)

사용자 승인: 2026-09-27, 제시한 명칭·스크롤·단계 그래프 계획에 “좋아 작업 진행 부탁해”. 현행 UI에서 학습 길은 학습 로드맵으로 통일한다. r0.2 돌아가기 계약도 같은 명칭을 사용한다.

- 작업 목록은 제목/닫기·하단 버튼을 고정하고 본문만 스크롤한다. 최대 85dvh, 둥근 외곽 안쪽 여백, 얇은 둥근 녹색 스크롤바와 옅은 트랙. 모바일은 OS 기본 터치 스크롤을 유지하고 스크롤바를 강제로 숨기지 않는다. SPEC-012 포커스·Escape·스크롤 잠금·모션 계약 유지.
- 각 진행 중(active, ‘이어서 할 일’) 카드의 상태 행 아래, 제목 위 중앙에 5개 원형 노드를 연결한 작은 로드맵을 둔다. 짧은 이름은 개념/문제/준비/실행/회고이며 상세의 5단계와 같은 의미다.
- 완료=녹색 원+체크, 현재=이중 강조 테두리+번호+‘현재’ 문구, 예정=옅은 빈 원+번호. 실제 현재 단계명도 텍스트로 유지한다. 색만으로 구분하지 않고 현재 노드에 aria-current=step을 제공한다. 그래프는 탐색 버튼이 아니다.
- stages와 step은 기존 읽기 전용 projection을 재사용한다. 새 진행 상태 저장·스키마·XP·성공률·시간 비율·부캐 평가를 추가하지 않는다. 상세와 카드가 같은 단계 정의를 공유한다. 건너뜀은 기존 이해를 활용했다는 문구를 유지한다.
- 이번 카드 그래프 대상은 active 그룹. 대기·보류·완료·이전 가설의 상태 문구와 기존 재개 계약 유지.

T07 320/390/768/1280px에서 카드 그래프 5단계가 넘치지 않고 완료·현재·예정 표시가 실제 projection/상세와 일치. 저장 데이터 불변, 키보드 순서에 비조작 그래프가 끼어들지 않음.
T08 긴 목록에서 본문만 스크롤되고 헤더/하단 버튼 위치 유지, 이중 스크롤 없음. 휠·터치·키보드 탐색, Escape·포커스 복귀·모션 감소 확인. 메뉴/제목/돌아가기 문구에 학습 로드맵 사용.
