# SPEC-018 — 독자별 공개 랜딩

r0.1 · 2026-10-07 · L07-W01 · AUTH-029

승인 근거: 사용자가 검토된 세 독자용 기획을 수락하고 “이렇게 해서 랜딩 개선 진행해줘. 스펙 명세 먼저 할거지?”라고 요청했다. 이 문서는 그 기획의 구현 계약이다. 기획 수락을 실측 전환율 개선의 근거로 삼지 않는다.

## 1. 목적과 불변 범위

| 독자 | 전달할 것 | 주요 행동 | 경로 |
|---|---|---|---|
| 입문자 beginner | 예시를 따라 배우고 체험 | 기존 이름표 → 앱 | /beginner/ (내용은 v3.1) |
| 경험자 experienced | 내 프로젝트에 남는 결과물·사용 흐름 | 내 프로젝트에 적용해 보기 | /value/ |
| 반복 창업자 tester | 제품을 사용하고 개선 의견 제시 | 직접 써보고 의견 남기기 | /test/ |

기존 landing~landing-v3.2 소스는 계측 사본 동기화 이외에 바꾸지 않는다. 앱 학습 내용·LESSON·AREAS·스탯·권한·난이도는 그대로다. 새 랜딩에는 이름표 입력이나 프로젝트 데이터 인계가 없다. v31만 기존 계약대로 이름표 문장 한 개를 인계한다. 반복 창업자에게 사업 아이디어 검증/판정을 제공한다고 주장하지 않는다. 신규 피드백 백엔드·전송 보장은 범위 밖이다.

## 2. 선택창·URL·저장 계약

- `/`는 기존 v3.1을 사전 렌더한다. 처음 방문하고 선택 기록이 없을 때 선택창을 연다. 닫기·Escape·건너뛰기로 기존 내용을 즉시 볼 수 있다. 바깥 클릭은 닫지 않는다.
- 선택창은 native dialog, 제목/설명 연결, 키보드 포커스 격리, 열 때 제목에 포커스, 닫을 때 호출 버튼(첫 방문은 공용 설명 선택 버튼)으로 복귀한다. 세 선택지는 실제 href 링크다. JS가 없으면 공용 안내 줄의 세 직접 링크가 보인다.
- 첫 화면에 공용 안내 줄을 넣는다. 기존 sticky 상단바를 추가하지 않으며 기존 v3.1 내용·상호작용은 바꾸지 않는다. 공용 줄에 현재 설명과 `다른 설명 보기`, JS 없는 경우 직접 링크를 제공한다.
- 직접 URL `/beginner/`, `/value/`, `/test/`는 저장 선택보다 우선하며 자동 선택창을 열지 않는다. 직접 방문은 저장된 선호를 덮어쓰지 않는다. 메뉴에서 명시적으로 선택하면 저장한다.
- `/` 재방문 시 저장된 experienced/tester로 location.replace 한다. beginner/dismissed는 `/`에 머문다. 기존 `/`의 해시 링크는 입문 콘텐츠 직접 링크로 우선 처리한다. 리디렉션 문서에서는 v31 초기화·뷰 계측을 실행하지 않는다.
- 저장키 `vencubator.audience.v1`, JSON `{v:1, choice: beginner|experienced|tester|dismissed}`. 개인정보·숙련도 판정·앱 상태를 저장하지 않는다. 잘못된 버전/값은 기록 없음으로 취급한다. localStorage 실패 시 sessionStorage에 대체 저장하고, 둘 다 실패해도 현재 선택/닫기/탐색은 작동한다. 저장 실패 안내는 aria-live에 표시한다. 쿠키·로그인은 추가하지 않는다.
- 저장 우선순위는 세션 → 로컬(로컬 실패 후 세션 선택을 오래된 로컬보다 우선). 저장 성공 시 둘에 같은 값 기록. 기록을 삭제하면 첫 방문 상태다.
- 내부 경로는 고정 매핑만 사용한다. 검색 인자는 허용 문자 40자 이하의 utm_source/medium/campaign/content와 internal=0|1, lab만 보존한다. 자유 입력·외부 URL·임의 redirect는 전달하지 않는다.
- 앱 CTA: 입문 `/app/?from=v31`, 경험 `/app/?from=value`, 테스트 `/app/?from=test`. 새 from은 이름표 저장소를 읽지 않는다. 앱 도착 후 기존 시작 절차를 따른다. 의견 폼 자동 열기·자동 제출 없음.

## 3. 확정 화면 문구

기존 v3.1 문구는 SPEC-016 및 현재 코드 유지. 아래 새 화면 문구는 content.mjs에서 관리한다. 숫자·화살표 등 장식과 접근성 기술 설명은 구현 시 의미를 보존한다.

### 3.1 공용

- 브랜드 `vencubator`
- 설명 선택 버튼 `다른 설명 보기`
- 현재 설명 `차근차근 체험` / `가치 먼저 보기` / `제품 테스트하기`
- 선택창 소제목 `나에게 맞는 시작`
- 제목 `어떤 방식으로 Vencubator를 만나볼까요?`
- 도입 `아이디어를 배우고, 실행하고, 돌아보는 도구예요. 원하는 설명을 골라 주세요.`
- 1 `창업이 처음이에요` / `예시를 따라 한 단계씩 체험할래요.`
- 2 `창업을 조금 해봤어요` / `내 프로젝트에 어떤 도움이 되는지 빠르게 볼래요.`
- 3 `여러 번 창업해봤어요` / `직접 써보고, 쓸모와 아쉬운 점을 짚어볼래요.`
- 닫기 `닫기`; 건너뛰기 `선택하지 않고 둘러보기`
- 선택 저장 안내 `선택은 이 브라우저에 기억해요. 언제든 다른 설명으로 바꿀 수 있어요.`
- 저장 실패 `선택을 기억하지 못했어요. 지금은 계속 둘러볼 수 있어요.`
- 공용 프로토타입 고지 `현재는 프로토타입이에요. 프로젝트 기록은 이 브라우저에 저장돼요. 다른 기기와 자동으로 이어지지 않아요.`
- 앱 안내 `앱에서 이름을 정하고 프로젝트를 시작해요.`
- 공용 푸터 `작게 배우고, 직접 확인하고, 다음 결정을 남겨요.`

### 3.2 경험자 — 4개 구간

1. 가치: 소제목 `경험은 있으니까, 필요한 가치부터.` / h1 `배운 것을 내 프로젝트의 다음 행동으로.` / 설명 `알고 있는 개념도 내 상황에 쓰려면 한 번 더 정리가 필요하죠. Vencubator에서 짧게 배우고, 내 말로 적용하고, 실행 뒤의 관찰을 남겨 보세요.` / CTA `내 프로젝트에 적용해 보기` / 보조 링크 `어떤 결과가 남는지 보기`
2. 흐름: 제목 `하나의 개념에서, 하나의 실행까지.` / 단계 `짧게 배우기` — `필요한 개념을 읽고 문제로 확인해요.` / `내 프로젝트에 적용하기` — `대상과 확인할 질문을 내 말로 적어요.` / `실행하고 돌아보기` — `해본 일과 관찰을 남기고 다음 결정을 정리해요.`
3. 결과: 제목 `머릿속 생각을, 다시 꺼내 볼 기록으로.` / 설명 `적용한 문장, 해볼 일, 관찰한 근거가 프로젝트에 남아요. 다음에 무엇을 확인할지 돌아볼 수 있어요.` / 예시 표시 `가상 예시` / 예시 제목 `좋다는 말 다음에, 무엇을 물어볼까?` / 항목 `적용한 질문` — `지난번 점심을 고를 때 가장 번거로웠던 순간은 언제였나요?` / `해볼 일` — `직장인 한 명에게 지난 점심 선택 과정을 물어보기` / `관찰과 다음 결정` — `메뉴보다 이동 시간이 문제였다. 가까운 선택지를 먼저 확인해 보기.`
4. 현재 범위: 제목 `먼저, 한 프로젝트에 써보세요.` / 설명 `짧은 학습부터 적용 기록과 실행·회고까지 직접 살펴볼 수 있어요.` / 공용 프로토타입 고지·앱 안내 / 동일 CTA.

### 3.3 반복 창업자 — 제품 테스트

1. 소제목 `여러 번 시작해 본 분께.` / h1 `이번에는 Vencubator를 시험해 주세요.` / 설명 `창업 과정을 아는 눈으로 직접 써보세요. 실제로 도움이 된 순간과 흐름이 끊긴 순간을 듣고 싶어요.` / CTA `직접 써보고 의견 남기기` / 보조 링크 `무엇을 살펴보면 될까요?`
2. 제목 `한 번의 사용에서, 세 가지를 봐주세요.` / 단계 `프로젝트 하나 시작하기` — `지금 생각 중인 아이디어로 시작해 보세요.` / `학습 하나 적용해 보기` — `짧은 학습 뒤 내 프로젝트에 적용한 기록이 유용한지 봐주세요.` / `도움과 마찰 짚어보기` — `계속 쓰고 싶은 순간과 멈추게 된 순간을 하나씩 떠올려 주세요.`
3. 제목 `칭찬보다, 구체적인 한 장면.` / 질문 `어느 순간에 실제로 도움이 됐나요?` / `어디에서 막히거나 불필요하다고 느꼈나요?` / `다시 쓴다면, 어떤 일을 할 때일까요?` / 안내 `사용한 뒤 앱의 설정 → 의견 보내기에서 남겨 주세요. 전송 상태는 앱에서 확인해 주세요.` / 고지 `의견을 남기는 일은 선택이에요. 실제 고객·팀의 민감한 정보는 적지 않아도 돼요.`
4. 제목 `작은 제품을, 직접 써볼 차례.` / 공용 프로토타입 고지·앱 안내 / 동일 CTA.

## 4. 시각·접근성

경험자: v1의 밝은 배경·초록 계열·큰 제목·간결한 카드 리듬을 계승. 네 구간, 장시간 스크롤 체험 없음. 테스트: 짙은 초록 hero와 밝은 체크 항목으로 별도 목적 표현. 사용자 등급·점수·우열 표시는 없음.

390px에서 수평 넘침 0, 제목 1개, 새 button은 type=button, 본문/버튼 명암 대비 4.5:1 이상, 주요 컨트롤 44px 이상, focus-visible 표시. 선택창은 작은 높이에서도 내부 스크롤 가능. 무한/자동 스크롤·모션 없음, reduced-motion 존중. 외부 새 폰트·라이브러리·이미지 의존성을 추가하지 않는다. 색상은 audience/tokens.css에서 정의한다. 방문자 입력을 HTML로 조합하지 않는다.

## 5. 계측과 데이터

선택은 무작위 배정이 아니며 기존 EXP_KEY/VARIANTS를 덮어쓰지 않는다. 새 페이지는 실험 변형을 새로 배정하지 않는다.

| 이벤트 | 허용 필드 |
|---|---|
| audience_prompt | placement=first/reopen |
| audience_select | audience=beginner/experienced/tester/dismissed |
| audience_view | audience=beginner/experienced/tester |
| audience_cta | audience=beginner/experienced/tester, placement=hero/footer |

루트에서 다이얼로그를 보여준 동안에는 audience_view를 보류한다. 입문 선택·닫기 때 또는 dialog 없는 실제 페이지당 1회 기록. 리디렉션 중간 문서는 기록하지 않는다. 선택 닫기는 dismissed로 기록한다. 직접 방문에도 audience_view 기록.

app_open/project_create/feedback_open에 audience=beginner/experienced/tester/unknown 추가. app_open의 from=v31/value/test로 세션 문맥을 설정하며 그 외는 unknown으로 초기화한다. 이 값은 선택 수준의 자기 보고일 뿐이다. from=value/test는 기존 앱 진입 enum에 추가한다. GA4 호스트·DNT·internal·lab 차단 유지. 주소는 허용된 경로만, 쿼리·입력 문장은 전송하지 않는다. 모든 신규 필드는 로컬 버퍼에도 enum만 저장한다.

관찰 지표: 첫 선택창 건너뛰기 비율, 독자별 앱 진입/프로젝트 생성, tester의 feedback_open. 클릭은 의견 전송 성공을 뜻하지 않는다. 실제 만족도·전환 효과는 배포 후 사용자 연구로 검증한다.

## 6. 빌드·검증

site/scripts/build.mjs가 루트·beginner·value·test와 공용 assets/audience를 만든다. 초보 직접 경로는 앱 href를 절대 /app/로 보정하고 canonical은 `/`로 유지. 새 두 페이지는 각 경로를 canonical로 지정한다. sitemap에는 `/`, `/app/`, `/value/`, `/test/`를 넣는다(중복 입문 URL 제외). Google/Naver 메타·robots·_headers 보존. 기존 독립 랜딩 배포 산출물은 계측 동기화 시에만 재빌드한다.

| AC | 수용 기준 |
|---|---|
| AC-A01 | 첫 `/` 진입 시 세 선택·건너뛰기·닫기·Escape가 작동 |
| AC-A02 | 세 직접 URL은 저장값보다 우선하며 선택창 없음 |
| AC-A03 | 재방문 선호 이동·해시 우선·잘못된 저장·저장 불가 상황 처리 |
| AC-A04 | 모든 랜딩에서 재선택, 닫은 후 포커스 복귀, 키보드 격리 |
| AC-A05 | 경험자 4구간·테스터 테스트/의견 안내·문구·한 h1·가상 예시 |
| AC-A06 | 새 두 CTA는 올바른 from으로 앱, 과거 이름표를 가져오지 않음 |
| AC-A07 | 입문 v31 이름표 인계·기존 체험 회귀 통과 |
| AC-A08 | 계측 필드·enum·차단 조건·자유 텍스트 차단·뷰 중복 방지 |
| AC-A09 | 390/1440 화면·수평 넘침 0·포커스·명암·모션 감소 |
| AC-A10 | JS 없는 본문·직접 링크·앱 링크, 기본 경로 서버 응답 |
| AC-A11 | 메타·canonical·sitemap·robots·headers·구독립 랜딩 보존 |
| AC-A12 | 필수 단위·빌드·CP 검사 및 QA 실행/미실행 근거 기록 |

테스트: site/prototype/landing-v3/landing-v3.1/landing-v3.2/scripts 단위, checkpoint, 사이트 빌드. 브라우저 QA는 설치된 Playwright를 사용하며 없으면 설치하지 않고 미실행 기록. 캡처 site/qa-shots/audience-*.png. 운영 GA4 수신·실제 피드백 전송·독자별 사용성은 로컬 QA와 구분한다.
