# 사용자 행동 지표와 성공 기준

[GROWTH-PLAN](GROWTH-PLAN.md) 하위 문서. 아래 임계값은 업계 기준이 아니라 **이번 실험의 초기 의사결정 기준 제안**이다(PRODUCT-BRIEF §8과 같은 태도). 작은 표본에서는 비율과 함께 **분자/분모**를 항상 적는다.

## 1. 측정 원칙

- 아이디어 문장·고객 입력 같은 **자유 텍스트는 이벤트로 보내지 않는다.** 길이 구간 같은 파생값만 보낸다.
- 방문자 식별은 브라우저에 저장한 무작위 ID(쿠키·지문 수집 없음). 신청 시 이메일과는 연결하지 않고, 신청 폼에 같은 무작위 ID만 숨은 값으로 넣는다.
- 제외: 제작자·테스트 방문(내부 IP 대신 `?internal=1` 파라미터로 표시), 봇, 같은 ID의 24시간 내 중복 세션은 1명.
- 채널은 UTM `utm_source`로만 구분한다. UTM 없는 방문은 `direct`.

## 3. 지표 정의

| ID | 지표 | 정의 | 보는 이유 |
|---|---|---|---|
| V | 방문자 | 채널별 고유 방문자(`landing_view`) | 분모 |
| A1 | 자기 문장 입력률 | `idea_submit(source=mine)` 방문자 / V | 문제 공감·약속 이해 (GH-1) |
| A1s | 예시 사용률 | `idea_submit(source=sample)`만 한 방문자 / V | 관심은 있으나 자기 아이디어 부재 신호 |
| A2 | 3칸 도달률 | `card_progress(filled≥3)` / (A1+A1s 방문자) | 체험 가치 (GH-2) |
| A3 | 완성률 | `card_progress(filled=5)` / (A1+A1s 방문자) | 끝까지 끌고 가는 힘 |
| C1 | 신청률 | `signup_submit` 방문자 / V | 의도 (GH-3) |
| C1c | 완성자 신청률 | 5칸 완성자 중 신청 비율 | 경험 후 의도 |
| C2 | 인터뷰 신청 수 | `signup_submit(type=interview)` 고유 수 | 연구 모집 |
| C3 | 인터뷰 참석률 | 참석 / 일정 확정 | 약한 의도 걸러내기 |
| NS | **북극성: 적격 신청자** | A1이면서 filled≥3이고 신청한 고유 방문자 | 세 신호 동시 충족 |
| Q1 | 막힘 경험 | 인터뷰 참석자 중 최근 4주 구체적 막힘 + 대처 시도를 말한 비율 | H01 |
| G1 | 정직 표기 영향 | FAQ 연 방문자의 이후 진행률 vs 열지 않은 방문자 | GH-5 |

보조: 입력 문장 길이 구간(무의미 입력 추정), 챕터별 이탈 위치, 모바일/데스크톱 차이, `cta_prototype_click` / A3, 게시물 클릭률(채널 제공 수치가 있을 때).

## 4. 성공 기준 (채널 단위)

판단 최소 표본: **채널당 V ≥ 100, 체험 시작(A1+A1s) ≥ 30.** 못 미치면 “판단 보류”로 기록하고 결론을 내지 않는다.

| 지표 | 녹색(성공) | 노랑(보완) | 빨강(실패) |
|---|---|---|---|
| A1 자기 문장 입력률 | ≥ 20% | 10–20% | < 10% |
| A2 3칸 도달률 | ≥ 50% | 30–50% | < 30% |
| A3 완성률 | ≥ 30% | 15–30% | < 15% |
| C1 신청률 | ≥ 5% | 2–5% | < 2% |
| C1c 완성자 신청률 | ≥ 20% | 10–20% | < 10% |

전체(모든 채널 합) 기준:

| 지표 | 목표 |
|---|---|
| NS 적격 신청자 | ≥ 30명 |
| C2 인터뷰 신청 | ≥ 15명 → 참석 8~12명 확보 |
| C3 참석률 | ≥ 60% |
| Q1 막힘 경험 | 참석자의 50% 이상 (H01 기준과 동일) |

표본 주의: V=100에서 20%의 95% 신뢰구간은 대략 ±8%p다. 채널 비교는 **두 배 이상 차이**거나 구간이 겹치지 않을 때만 “차이 있음”으로 쓴다. W3 메시지 A/B에서 10% → 20% 차이를 보려면 대략 한 쪽당 200명 수준이 필요하다. 못 모으면 “결론 없음”으로 기록한다.

## 5. W4 종합 판정

| 판정 | 조건 | 다음 행동 |
|---|---|---|
| **Go** | NS ≥ 30 **그리고** 1개 이상 채널에서 A1·A3·C1 모두 녹색 **그리고** Q1 ≥ 50% | 해당 채널·메시지로 MVP 코호트(H02 15~25명) 모집 계획 확정, 신청자에게 베타 안내 |
| **Iterate** (최대 1회) | 참여 지표(A1~A3)는 녹색·노랑인데 C1이 노랑·빨강, 또는 NS 15–29 | [PIVOT-PLAYBOOK](PIVOT-PLAYBOOK.md)의 “제안(Offer)” 또는 “메시지” 피벗 1개만 적용해 2주 재실험 |
| **Pivot** | 표본을 채운 모든 채널에서 A1 빨강, 또는 Q1 < 50% | [PIVOT-PLAYBOOK](PIVOT-PLAYBOOK.md) 진단표로 대상·문제·제안 중 하나를 바꿔 새 라운드 |
| 중단 검토 | 피벗 2회 뒤에도 어느 채널도 녹색 3개 미달 | 사용자와 제품 방향 재검토 (자동 결정 아님) |

판정은 수치만으로 확정하지 않는다. 인터뷰에서 **“지금 무엇으로 대신하고 있고, 무엇을 잃고 있는지”**가 구체적으로 나왔는지를 함께 본다. “좋네요, 써볼게요”는 수요로 세지 않는다(PRODUCT-BRIEF H09 원칙).

## 6. 대시보드 (주 1회)

1. 채널별 퍼널: V → A1 → A2 → A3 → C1 (분자/분모 병기)
2. 챕터별 이탈: 어느 챕터에서 가장 많이 멈추는지
3. 메시지별 A1·C1 (W3)
4. 누적 NS, 인터뷰 신청·확정·참석
5. 질적 기록: 댓글·인터뷰 주제 상위 5개와 빈도

## 7. 질적 신호 수집

- 게시물 댓글: 주제별 태그(가치 공감 / 사용성 문제 / 신뢰 의문 / 대상 불일치 / 기능 요청)로 분류해 [EXPERIMENT-LOG](EXPERIMENT-LOG.md)에 누적.
- 인터뷰 가이드(20분, 판매 없음): 최근 4주 안에 아이디어를 확인하려다 멈춘 순간 → 그때 한 일 → 쓴 도구·사람·비용 → 카드 체험 중 가장 쓸모 있던 칸 / 쓸모없던 칸 → “다음 주에 실제로 할 한 가지”. 기존 [사용성 진행표](../docs/validation/PROTOTYPE-RESEARCH-KIT.md)의 동의·익명 ID 규칙을 그대로 따른다.

## 8. 랜딩 v1/v2 비교 (SPEC-009, 2026-09-25)

| 단계 | 이벤트 | 두 변형 공통 |
|---|---|---|
| 방문 | `landing_view` | ✓ |
| 서비스 진입 클릭 | `cta_click` | ✓ |
| 앱 도착 | `app_open` (from) | ✓ |
| 첫 프로젝트 | `project_create` (from, imported) | ✓ |
| 첫 학습 완료 | `lesson_complete` | ✓ |
| 자기 문장·카드 | `idea_submit`, `card_progress` | v2만 (보조) |

- 비교 지표: 변형별 **첫 프로젝트 생성률** = `project_create` 방문자 / `landing_view` 방문자. 보조: 진입 클릭률, 첫 학습 완료율.
- 필요한 표본(유의수준 5%, 검정력 80%): 10%↔20% 차이는 변형당 약 200명, 10%↔15%는 약 680명. 부족하면 “방향 참고”로만 기록한다.
- 강제 지정(`?v=`)·내부 방문은 비교에서 뺀다. 방문자 ID의 첫 배정만 쓴다. 변형 × 채널로 나눠 본다.
- 적격 신청자(NS) 정의는 그대로 두되, v1 방문자는 문장 입력이 없으므로 “앱에서 첫 프로젝트 생성 + 신청”을 v1의 적격 조건으로 본다.
