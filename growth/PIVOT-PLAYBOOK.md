# 피벗 플레이북

[METRICS §5](METRICS.md) 판정이 Iterate 또는 Pivot일 때 사용한다. 피벗 후보를 **미리** 적어 두는 이유는 결과를 본 뒤 그럴듯한 이야기를 지어내지 않기 위해서다.

## 1. 규칙

1. **한 라운드에 하나만 바꾼다.** (메시지 / 채널 / 대상 / 문제 / 제안 / 체험 형식 중 하나)
2. 라운드는 2주, 판단 표본은 METRICS §4와 같다.
3. 바꾸기 전 [EXPERIMENT-LOG](EXPERIMENT-LOG.md)에 “무엇을, 왜, 무엇이 나오면 성공인지”를 먼저 적는다.
4. 제품 철학(결정은 사용자, 점수≠성공, 근거와 가설 구분, 반박도 성장)은 피벗 대상이 아니다. 이걸 바꿔야만 수요가 생긴다면 그것은 피벗이 아니라 **다른 제품**이므로 사용자와 따로 논의한다.
5. 대상·문제·제안 피벗은 PRODUCT-BRIEF·SPEC 개정이 필요한 **제품 결정**이다. Decision Request로 올리고 사용자 승인 후 진행한다. 메시지·채널·체험 형식 조정은 이 계획 범위 안에서 진행할 수 있다.

## 2. 증상 → 진단 → 피벗

| 증상 (어디서 새나) | 가능한 원인 | 확인 방법 | 우선 피벗 |
|---|---|---|---|
| 게시물 클릭이 적다 | 채널-대상 불일치, 헤드라인이 약함 | 채널 제공 노출/클릭, 댓글 톤 | **메시지**(M-A↔M-B↔M-C) → 그래도 낮으면 **채널** |
| 방문은 많은데 A1(자기 문장) 낮음, A1s(예시)는 높음 | 관심은 있으나 **지금 아이디어가 없는** 사람들 | 인터뷰·댓글: “아이디어가 없어서” | **대상**: 아이디어가 있는 사람이 모이는 채널로 / 히어로에 “아이디어 없어도 예시로” 강조 |
| A1·A1s 모두 낮음 | 약속이 와닿지 않음, 문제 자체가 약함 | 히어로 이탈, Q1 | **문제** 피벗 후보 검토(P-2~P-4) |
| A1은 높은데 A2 낮음(퀴즈·질문 챕터 이탈) | 학습 단계가 번거로움, 설문 느낌 | 챕터별 이탈, 모바일 비중 | **체험 형식**: 3칸 버전(아이디어→질문→결정) 비교 |
| A2·A3 높은데 C1 낮음 | 체험으로 충분, 계속 쓸 이유가 약함 | C1c, 인터뷰 “다음에 무엇이 필요한지” | **제안(Offer)** 피벗(O-2~O-4) |
| C1 높은데 인터뷰 참석률 낮음 | 의도가 약함, 신청 부담 없음 | 확정·참석 비율 | 신청 단계에 “이번 주 확인하고 싶은 것 한 줄” 추가(자격 질문) |
| Q1 < 50% (막힌 경험 없음) | 대상이 이미 검증에 익숙하거나 문제 자체가 가벼움 | 인터뷰 기록 | **대상** 또는 **문제** 피벗 |
| 특정 채널만 녹색 | 채널 특이적 수요 | 채널별 퍼널 | 피벗 아님 → 해당 채널 **집중**, MVP 모집 채널로 확정 |

## 3. 미리 정한 피벗 후보

### 대상 (Segment)

| ID | 대상 | 근거·가설 | 찾을 곳 |
|---|---|---|---|
| S-1 | (현재) 만들 수 있는 1인 빌더 | DR-01, A02 | GeekNews, 디스콰이엇, SYDE |
| S-2 | 대학생 예비 창업자·창업동아리 | 비개발자, 과제·공모전 등 **마감**이 행동 동기 | 창업지원단·동아리(CH-6) |
| S-3 | 정부 지원사업 준비자 | 사업계획서에 쓸 **고객 검증 근거**가 필요 | 창업 교육·지원기관 커뮤니티 |
| S-4 | 직장인 사이드 창업자·사내벤처 담당 | 시간이 부족, 짧은 단위 학습 선호 | LinkedIn(CH-5) |
| S-5 | 창업 교육자·멘토 (B2B2C) | 수강생 과제 도구로 사용 | 강사·운영진 직접 연락 |

### 문제 (Problem)

| ID | 문제 정의 | 제품 영향 |
|---|---|---|
| P-1 | (현재) 무엇을 먼저 확인할지 몰라 멈춘다 | 현 제품 그대로 |
| P-2 | 고객 인터뷰 질문을 만들고 기록하기가 어렵다 | 7영역 중 고객 이해만 깊게, 좁은 도구 |
| P-3 | 지원서·사업계획서에 넣을 검증 근거를 정리하기 어렵다 | 근거·결정 내보내기 기능이 핵심이 됨 |
| P-4 | 팀 안에서 아이디어 판단 기준을 합의하기 어렵다 | 협업(현재 MVP 제외 범위) 필요 — 가장 큰 변경 |

### 제안 (Offer)

| ID | 제안 | 검증 방식 |
|---|---|---|
| O-1 | (현재) 셀프 학습 앱 베타 알림 | 신청 |
| O-2 | 4주 “고객 검증 챌린지” 코호트 (주 1회 과제 + 도구 + 짧은 피드백) | 모집 글, 정원 10명 신청률 |
| O-3 | 인터뷰 질문·기록 템플릿 무료 제공 → 도구로 연결 | 템플릿 요청률, 이후 체험률 |
| O-4 | 교육기관용 60분 워크숍 키트 | 기관 응답·도입 의향 |

O-2는 사람의 개입이 들어가므로 “AI 코파일럿” 약속과 다르다. 수요가 확인되면 어떤 부분을 제품으로 옮길지 따로 결정한다.

### 메시지·체험 형식

- 메시지: M-A(문제 공감) / M-B(즉시 결과물) / M-C(정직·반박) — [CHANNELS §2](CHANNELS.md)
- 체험 형식: 랜딩 v2 5칸(기본) / 3칸 단축판 / 랜딩 v1(설명형) — 형식 변경은 landing-v2 SPEC-007 개정 절차를 따른다.

## 4. 피벗 결정 기록 양식

```
## PIVOT-NN · YYYY-MM-DD
- 판정 근거: (METRICS 지표, 분자/분모, 인터뷰 요지)
- 바꾸는 것 하나: (예: 대상 S-1 → S-2)
- 바꾸지 않는 것: (제품 철학, 측정 방식 등)
- 성공 조건: (예: 창업동아리 채널 A1 ≥ 20%, C1 ≥ 5%, V ≥ 100)
- 필요한 승인: (DR 번호 / 없음)
- 기간: 2주 (시작일~종료일)
```
