# 랜딩 v3.2 메시지 개정 정책

기준일 2026-09-30 · 승인 AUTH-028(사용자 요청 2026-09-30: “v3.2로 작성해줘”) · 계약 [SPEC-017](SPEC-017-landing-v3.2.md) · 작업 지시·프롬프트 [WORKORDER](WORKORDER.md) · W `L06-W01` · 구현 담당: GPT(사용자 PC 에이전트)

## 1. 왜 v3.2인가

v3.1 공개(2026-09-29) 뒤 여러 사용자에게서 같은 평가가 나왔다.

> **“누구를 위해, 어떤 가치를 제공하는지 모호하다.”**

| # | 원인(코드 확인: `landing-v3.1/src/content.mjs`) |
|---|---|
| M1 | **가장 큰 글씨가 은유다.** h1 “아이디어를 심으면, / 근거가 뿌리내려요.”는 결과가 아니라 분위기를 말한다. 방문자가 해석해야 한다 |
| M2 | **대상이 가장 작은 글씨이고 내부 용어다.** eyebrow “1인 빌더를 위한 창업 학습 코파일럿”. ‘1인 빌더’·‘코파일럿’은 방문자가 자기를 부르는 말이 아니다 |
| M3 | **lead가 가치 대신 조작법을 설명한다.** “이름표에 적어 심어 보세요, 아래로 내려갈수록…” — 끝나면 무엇이 남는지 없다 |
| M4 | **은유가 겹겹이 쌓였다.** 이름표·심기·지층·cm·겉흙·속흙·부엽토·뿌리·부캐·본캐 |
| M5 | **카테고리가 흔들린다.** 학습 앱인가, 검증 도구인가, AI 코파일럿인가. 아래 FAQ는 “AI가 아니라 템플릿”이라고 한다 |
| M6 | **가치를 체험해야만 안다.** 입력하지 않는 약 80%(GA4 2026-09-28~29: 입력 11 / 랜딩 54)는 무엇을 해 주는지 모른 채 떠난다 |

v3.2의 목표 한 줄: **첫 화면 5초 안에 “누구를 위한 것인지”와 “쓰면 무엇을 얻는지”를 평이한 말로 알게 한다. 뿌리 세계관은 체험 속 시각 요소로 남긴다.**

## 2. 포지셔닝 결정 (기본값, DR-LM-01)

PRODUCT-BRIEF §1 약속: “오늘 할 작은 행동 하나를 찾고, 실행한 결과로 내 아이디어를 한 단계 더 분명하게 만든다.”

| 항목 | 결정 |
|---|---|
| 앞세울 가치 | **만들기 전에 무엇을 확인할지 알게 된다** (검증의 다음 행동) |
| 학습의 위치 | 수단. “배우면서 확인한다”로 보조 설명 |
| 대상 호칭 | 방문자가 쓰는 말: **“사이드 프로젝트·1인 창업을 준비하는 메이커”** (DR-01 대상과 같음: 만들 수는 있지만 고객 검증 경험이 적은 사람) |
| 카테고리 한 줄 | “내 아이디어로, 만들기 전에 확인하는 법을 배우는 도구” |
| 쓰지 않는 말(첫 화면) | 코파일럿, 1인 빌더, 부캐·본캐, 심기·뿌리·이름표·흙 등 은유 |

사용자가 “학습”을 앞세우기로 바꾸면 SPEC-017 §7.1 참고안 C′(학습형)를 후보로 올리고 이 표를 먼저 고친다.

## 4. 메시지 원칙

| ID | 원칙 | 적용 |
|---|---|---|
| MP-1 | **평이한 말이 먼저, 은유는 뒤.** 방문자가 가장 먼저 읽는 자리(eyebrow·h1·lead·가치 3줄·주 버튼·층 제목·하베스트 제목)에는 은유어를 쓰지 않는다 | 은유는 그림(새싹·뿌리·깊이 눈금), 작은 보조 라벨(`겉흙 · 0–15cm`)에만 |
| MP-2 | **누가 → 무엇을 얻나 → 어떻게** 순서 | eyebrow = 누가, h1 = 핵심 가치, lead + 가치 3줄 = 얻는 것, 입력칸 = 어떻게 |
| MP-3 | **결과물로 말한다.** “자란다·쌓인다” 대신 손에 남는 것을 셀 수 있게 | “질문 3개”, “오늘 확인할 것 하나”, “다음 한 걸음” |
| MP-4 | **대상은 방문자의 말로** | “사이드 프로젝트·1인 창업을 준비하는 메이커” |
| MP-5 | **중복 제거** | h1이 문제를 말하므로 v3.1 `hook`(문제 질문)은 첫 화면에서 뺀다. 고민 공감은 겉흙 층 “이런 적 있나요?”가 계속 맡는다 |
| MP-6 | **정직 유지** | 금지 표현(`CLAIM_BANNED`), 가상 예시·프로토타입·이 브라우저에만 고지 유지. 시간 표기는 사용성 확인 전까지 숫자 대신 “몇 분” |

## 6. 성공 판단

### 6.1 병합 전: 5초 테스트 (필수, 사용자 진행)

- 자료: 단계 4에서 만든 390×844 첫 화면 캡처 4장(`landing-v3.2/qa-shots/5sec-v31.png`, `5sec-a.png`, `5sec-b.png`, `5sec-c.png`). 배포 없이 휴대폰에 띄워 쓴다.
- 대상: 5~8명. 가능하면 “모호하다”고 말해 준 사람 포함 + 처음 보는 사람 절반 이상.
- 방법: 첫 화면만 5초 보여 주고 가린 뒤 묻는다. ① “누구를 위한 서비스 같나요?” ② “쓰면 무엇을 얻을 것 같나요?”
- 정답 기준: ① “아이디어가 있는 사람 / 사이드 프로젝트·창업 준비하는 사람” 계열 ② “무엇을 확인할지 / 고객에게 물어볼 질문 / 다음에 할 일” 중 하나 이상.
- **통과: 두 질문 모두 맞힌 사람 ≥ 5명 중 4명.** 같은 사람에게 v3.1과 후보안을 순서를 바꿔 보여 주면 비교도 된다.
- 후보 a가 미달이고 b·c 중 통과안이 있으면 `SITE.headline`만 바꿔 재빌드하고 SPEC-017 §7.1의 “기본” 표시를 옮긴다.
- 결과는 `growth/EXPERIMENT-LOG.md`와 `landing-v3.2/docs/VAL-L32.md`에 기록.

## 7. 작업 방식

- v3.1과 같다: GPT에 프롬프트 하나로 W 하나(`L06-W01`), 브랜치 하나, PR 하나. 단계마다 의미별 커밋·CP.
- 명세와 다르게 가야 하면 SPEC-017을 먼저 고치고 PR 본문에 적는다.
- main 병합·배포는 사용자.
