# 랜딩 v3.1 개선 정책

기준일 2026-09-29 · 승인 AUTH-027(사용자 요청 2026-09-29) · 계약 [SPEC-016](SPEC-016-landing-v3.1.md) · 작업 지시 [WORKORDER](WORKORDER.md) · 구현 담당: GPT(사용자 PC 에이전트)

> 사용자 요청: “기존 v3은 내버려두고 v3.1으로 개선하자. 개선 정책을 작성해줘. 실제 작업은 GPT를 통해 개선하려고 해.”

## 1. 왜 v3.1인가

v3(뿌리)는 체험 흐름과 정서는 좋았지만 테스터에게서 세 가지 피드백이 나왔다.

| # | 피드백 | 원인(코드 확인) |
|---|---|---|
| F1 | 액션을 했는데 다음에 무엇을 해야 할지 모르겠다 | “심기”만 다음 층으로 이동. 나머지 행동(예시 칩·퀴즈·질문 저장·관찰·결정) 뒤에는 다음 행동 안내가 없다 |
| F2 | 대상 고객과 공감이 부족하다 | 첫 화면이 은유로 시작하고 문제 공감 문장이 없다. 예시가 1인 빌더와 거리가 있다. 관찰 답 3개가 팀플 예시에 고정돼 다른 아이디어에서 맥락이 깨진다 |
| F3 | ‘앱 열기’ 버튼을 인지하지 못한다 | 상단바 작은 버튼(14px) 하나. 짙은 흙 구간에서 버튼과 상단바 대비 2.22:1(권장 3:1 미달). 첫 화면 본문에 앱으로 가는 길이 없다. ‘앱’이 설치로 읽힌다 |

v3.1의 목표는 한 줄이다. **“방문자가 층마다 무엇을 끝냈고, 다음에 무엇을 하면 되는지, 언제든 앱으로 갈 수 있다는 것을 알게 한다. 그리고 첫 줄에서 ‘내 이야기’라고 느끼게 한다.”**

## 2. 불변 규칙 (v3 보존)

| ID | 규칙 |
|---|---|
| PV-1 | `landing-v3/` 폴더의 동작·카피·스타일·명세는 바꾸지 않는다. 유일한 예외: 공통 계측 파일 `track.mjs` 복사본 동기화(SPEC-009 §4 “원본은 site/shared, 같은 내용으로 복사”)와 그에 따른 `landing-v3/dist/index.html` 재빌드. v3 화면 결과는 달라지지 않아야 한다 |
| PV-2 | v3.1은 새 폴더 `landing-v3.1/`에서 만든다. v3를 복사해 시작하고, v3 파일을 import하지 않는다(독립 빌드) |
| PV-3 | v3.1의 식별자는 v3와 섞이지 않는다: 변형 `v31`, 저장 키 `vencubator.landing.v31`, 앱 진입 `./app/?from=v31`, 개발 서버 4177, QA 서버 4197 |
| PV-4 | 운영 루트(`/`)를 v3.1로 바꾸는 것은 마지막 단계(단계 5)에서만, 사용자 main 병합으로 공개된다. 그 전까지 v3가 운영 랜딩이다 |

## 3. 계승하는 원칙 (SPEC-010·PRINCIPLES)

- DP-1 한 시점에 한 초점: 층마다 **주 버튼은 “다음 층” 하나**. 앱 링크는 보조(텍스트 링크)로.
- DP-7 정직: 앱으로 넘어가는 것은 **이름표 문장뿐**. “기록이 모두 옮겨져요” 같은 표현 금지. 가상 예시 표기 유지. 금지 표현(`CLAIM_BANNED`) 유지.
- DP-11 스크롤 주도권: 자동 스크롤은 “심기” 하나만. 나머지는 버튼을 눌러야 이동. sticky는 상단바만.
- DP-12 가만히 있어도 완성: 조작 전에도 예시 기록이 보인다.
- 은유 + 실제 뜻 병기: 새 버튼 문구도 “더 깊이 뿌리 뻗기 · 물어볼 질문 만들기”처럼 뜻을 함께 쓴다.
- 접근성: 새 버튼은 `type="button"`, 새로 열리는 안내는 `aria-live="polite"`, 모션 감소 시 즉시 최종 상태, 390px에서 가로 스크롤 0.
- 개인정보: 자유 텍스트는 계측하지 않는다. 새 이벤트는 정해진 값(enum)만.
- 퀴즈 문항(`LESSON`)과 7영역(`AREAS`)은 앱(prototype)과 일치해야 하므로 v3.1에서 바꾸지 않는다.

## 4. 개선 정책

### 4.1 다음 행동 안내 (F1)

- **층 완료 → “다음 층” 버튼이 뿌리처럼 뻗어 나타난다.** 완료 여부는 상태에서 파생(새로고침해도 유지, 복원 시 애니메이션 없음).
- 위치: 방금 조작한 패널 **바로 아래 오른쪽**(DR-LG-01 기본값). 사용자가 요청한 “우측”을 유지하되, 행동 직후 시선이 있는 자리에 둔다. 층 우측 상단은 행동 시점에 화면 밖이라 채택하지 않았다.
- 화살표는 `↓`(땅속 방향, DR-LG-02).
- 등장 모션은 새 모션 L3M-08 “뿌리 뻗기”(기존 L3M-06 진입 효과는 0.35 불투명에서 시작해 비활성처럼 보여 버튼에는 쓰지 않는다).
- 고객 입력 후 저장을 안 누른 경우 저장 버튼을 강조한다(X-3).

### 4.2 앱으로 가는 길 (F3 + 요청 B)

- **보이게**: 상단바 CTA를 키우고(16px), 짙은 흙 구간에서 연두 배경으로 바꿔 대비 ≥ 3:1(연두/부엽토 10.67:1).
- **말이 통하게**: “앱 열기” → 상단바 “앱 시작하기”, 첫 화면 보조 링크 “가입 없이 바로 앱에서 시작하기 →”, 층마다 “여기까지 하고 앱에서 이어하기 →”(DR-LG-03 기본값).
- **행동마다 반응하게**: 층을 끝낼 때마다 CTA에 빛이 한 번 지나가고 진행 점(○○○○○)이 하나 채워진다. 5층을 모두 채우면 한 번 크게 반응 + 말풍선. 첫 “심기” 때 말풍선으로 버튼 위치를 알린다. **무한 반복 펄스 금지**(DR-LG-04 기본값).

### 4.3 대상 고객 공감 (F2)

- 첫 화면은 **문제로 시작**: 제목 위에 “아이디어는 있는데, 뭘 먼저 확인해야 할지 몰라 멈춰 있나요?”(growth M-A와 같은 메시지). 은유 제목은 유지.
- **“이런 적 있나요?”** 네 가지 중 하나를 고르면(선택 사항) 겉흙 층 도입 문장이 그 고민에 맞춰 바뀐다. 선택 값만 계측(`pain_select`) → H01(막힘 경험) 신호.
- **예시를 1인 빌더 쪽으로**: 프리랜서 정산 도구·쇼핑몰 리뷰 답글·팀플 동료(기존 유지).
- **관찰 답을 예시별로**: 고른 예시에 맞는 답 3개. 내 아이디어면 특정 분야에 묶이지 않은 답.
- 층마다 “왜 이게 당신에게 필요한지” 한 줄.
- 하베스트 문구는 “다시 해야 한다”보다 “앱에서는 진짜 고객과 한 바퀴를 돈다”는 이유를 먼저.
- 만든 사람 이야기(EM-6)는 **이번 범위에서 제외**. 제작자의 실제 경험 문장을 사용자가 주면 별도 작업으로 넣는다(지어낸 경험담·가짜 후기 금지).

## 6. 성공 판단

| 지표 | 정의 | 방향 |
|---|---|---|
| 층 간 진행률 | 층 n 완료 → 층 n+1 도달(REACH) | v3 대비 상승 |
| 5층 완료율(A3) | `card_progress(filled=5)` / 체험 시작 | 상승 |
| 앱 진입률 | `cta_click` 방문자 / `landing_view`, `app_open(from=v31)` | 상승 |
| 첫 프로젝트 | `project_create(from=v31)` / 방문 | 상승(북극성 보조) |
| 고민 선택률 | `pain_select` 방문자 / 방문, 값 분포 | 신규(H01 신호) |

- **사용자 작업**: 전환 전 GA4에서 v3의 최근 2주 기준선(층별 도달·`cta_click`·`app_open`)을 기록해 둔다. 표본이 작으면 “방향 참고”로만(METRICS §4).
- **사용성 확인(5명)**: ① 아이디어 하나로 끝까지 ② “이제 앱에서 이어서 해 보세요” — 앱 버튼 찾는 시간, 층별 멈춤 위치.

## 7. 작업 방식

- 원스텝: GPT에 프롬프트 하나를 보내 W 하나(`L05-W01`), 브랜치 하나, PR 하나로 단계 1~5를 끝까지 수행한다(SPEC-014 §12). 단계마다 의미별 커밋과 CP를 남겨 중단돼도 이어갈 수 있게 한다. 내용은 [WORKORDER](WORKORDER.md), 프롬프트는 [PROMPTS](PROMPTS.md).
- main 병합·배포는 사용자.
- 명세와 다르게 가야 하면 코드보다 SPEC-016을 먼저 고치고 PR 본문에 적는다.
