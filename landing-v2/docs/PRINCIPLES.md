# 랜딩 v2 설계 원리 — 분석 → 원리 추출 → 독립 표현

기준일 2026-09-24 · 대상 `landing-v2/` · 계약은 [SPEC-007](SPEC-007-landing-v2.md)

v2의 목표는 **“더 나은 UI/UX를 줄 수 있다면 구현한다”**이다. 그래서 참고 사이트의 섹션 구성과 연출을 가져오지 않았다. 참고 사이트에서 **왜 효과가 있었는지**만 뽑아낸 뒤, Vencubator의 제품 방식으로 다시 표현했다.

## 0. v1 회고 — 무엇이 문제였나

| 관찰 | 원인 | v2 원칙 |
|---|---|---|
| 섹션 순서·연출이 TTJ와 1:1 대응 (히어로 축소 → 3문장 교차 → 원칙 → 경로 → 그리드 → 숫자 브리지 → 5프레임 → 3카드 → 일정 → CTA) | “기법 → 적용 매핑” 표를 기준으로 설계했다. 기법이 곧 구성이 되었다 | 기법이 아니라 **원리**를 추출하고, 구성은 제품 흐름에서 도출한다 |
| 방문자는 스크롤하며 **읽기만** 한다 | 설명형 랜딩의 기본값을 그대로 따랐다 | 제품이 “해보며 배우기”라면 랜딩도 **해보게** 한다 |
| 화면 고정 스테이지 3곳(320svh·230svh·500svh)이 스크롤을 붙잡는다 | 참고 사이트의 몰입 연출을 가져왔다 | 스크롤 속도는 방문자가 정한다. **스크롤 고정 없음** |
| 앱 화면 목업이 제품을 “보여주기”만 한다 | — | 목업 대신 **실제로 조작되는 작은 버전** |
| 목차·챕터 번호·진행 막대가 따로 존재한다 | 위치 표시 기법을 그대로 가져왔다 | 위치 표시 = 방문자가 만든 결과물의 진행 상태 |

## 1. 분석 — 세 가지 출처

### 1-1. TTJ에서 관찰한 것 (구현이 아니라 효과)

| 관찰된 장치 | 방문자에게 준 효과 |
|---|---|
| 스크롤로 문장이 교차하는 고정 구간 | 한 번에 한 메시지만 보여 집중이 유지됨 |
| 21 → 05 숫자 전환 | 복잡함(21)이 실행 가능한 크기(5)로 줄어드는 안도감 |
| 챕터 번호 + 진행 막대 | 긴 페이지에서도 지금 위치와 남은 양을 앎 |
| 히어로 이후 하단 CTA | 마음이 생긴 순간 바로 행동할 수 있음 |
| 실제 작업 사진·코드리뷰 이미지 | 말보다 결과물이 신뢰를 만듦 |
| smoothstep 이징, 모션 감소 대응 | 부드럽지만 과하지 않음, 접근성 존중 |

### 1-2. Vencubator 제품에서 온 것 (PRODUCT-BRIEF, SPEC-002/005, prototype)

- 한 문장이면 시작한다. 다음 학습 하나만 안내한다.
- 개념 → 문제 → 응용 → **내 프로젝트 결과물** → 실행 → 회고.
- AI는 묻고 정리할 뿐, **결정은 사용자**가 한다.
- 근거와 가설을 구분하고, **반박도 성장**이다. 반박되면 전략 학습을 앞당긴다(SPEC-005 결정형 규칙).
- 점수·성공률 대신 “무엇을 새로 알고 무엇을 바꿨는가”로 보여준다.
- 부캐(프로젝트)와 본캐(학습)는 따로 자란다.

### 1-3. 첫 방문자의 과제 (H01 가설 대상: 1인 빌더)

1. “이게 나한테 쓸모 있나?”를 **5초 안에** 판단하고 싶다.
2. 말보다 **내 아이디어에 적용된 모습**을 보고 싶다.
3. 가입이나 설치 부담 없이 **1분 안에** 체감하고 싶다.
4. AI 서비스에 대한 경계: 결과를 과장하지 않는지, 내 데이터가 어디로 가는지 알고 싶다.

## 2. 추출한 설계 원리

| ID | 원리 | 근거 (1-1/1-2/1-3) |
|---|---|---|
| DP-1 | **한 시점에 한 가지 초점.** 한 화면에서 방문자가 해야 할 일은 하나 | TTJ 교차 구간의 집중, 제품의 “다음 학습 하나” |
| DP-2 | **복잡함을 실행 가능한 크기로 줄여 보여준다** | 21→05의 안도감, 7개 영역 중 오늘 하나 |
| DP-3 | **위치 = 진척.** 페이지 진행을 추상 번호가 아닌 의미 있는 결과물로 보여준다 | 챕터 번호의 효과 + 제품의 결과물 중심 |
| DP-4 | **말보다 결과물.** 설명 대신 방문자 자신의 아이디어로 만든 결과물 | 작업 사진 신뢰, 방문자 과제 2 |
| DP-5 | **전환 경로는 항상 가까이, 하지만 방해하지 않게** | 하단 CTA, 과제 3 |
| DP-6 | **해보며 이해한다.** 핵심 개념은 읽기보다 한 번의 조작으로 전달 | 제품 철학 learn-by-doing |
| DP-7 | **정직이 신뢰다.** 예시·가상·미구현을 화면에서 구분 | 제품 원칙, 과제 4 |
| DP-8 | **모션은 상태 변화를 설명할 때만.** 장식 모션 최소, 스크롤 고정 없음, 모션 감소 시 즉시 상태 | TTJ 이징의 절제 + v1 회고 |

## 3. 독립 표현 — 컨셉 “아이디어 카드”

> 방문자가 한 문장을 쓰면, 페이지를 내려가는 동안 **자기 아이디어의 첫 번째 카드**가 채워진다. 페이지를 다 읽으면 카드 한 장이 완성되고, 그 카드로 프로토타입을 시작한다.

카드는 프로토타입의 실제 데이터 흐름(아이디어 → 배운 개념 → 내 질문 → 관찰 → 결정)을 작게 옮긴 것이다. 카드에 붙은 새싹은 채워진 칸 수만큼 자란다.

| 원리 | v1 표현 (참고 사이트 대응) | **v2 표현 (독립)** | 더 나아진 UX |
|---|---|---|---|
| DP-1 | 화면 고정 후 문장 3개 교차 | 챕터마다 **질문 하나 + 조작 하나**. 스크롤 고정 없음 | 스크롤 주도권 회복, 접근성·모바일 안정 |
| DP-2 | 7 → 1 숫자 전환 | 히어로 “걱정 구름”이 첫 챕터에서 **한 문장으로 수렴** + 7개 영역 경로에서 **오늘 칸 하나**만 켜짐 | 줄어드는 대상이 방문자 자신의 걱정 |
| DP-3 | 챕터 번호 `01/07` + 진행 막대 | **아이디어 카드 = 목차 = 진행 표시.** 칸을 누르면 해당 챕터로 이동 | 위치 표시가 곧 결과물 |
| DP-4 | 앱 화면 목업, 5프레임 연출 | 방문자 문장·고객이 들어간 **실제 질문 3개**가 즉석에서 생성 | “내 것”이라는 소유감 |
| DP-5 | 하단 스티키 CTA 바 | 카드 하단 CTA(데스크톱) / **하단 카드 트레이**(모바일): 진척 `n/5`와 CTA를 함께 | CTA에 이유(내 카드)가 붙음 |
| DP-6 | 문제 풀이 화면 목업 | **실제로 풀 수 있는 퀴즈 1문항**, 오답이면 다른 문항 | 개념을 몸으로 이해 |
| DP-6·7 | “반박도 성장” 카드 설명 | 예시 관찰에서 **같았어요/달랐어요**를 고르면 카드에 “가설 재검토” 표시가 붙고, 아래 7개 영역 경로의 순서가 바뀜(전략 앞당김) | 제품 규칙을 직접 체험 |
| DP-7 | 푸터 고지 | 예시 값은 흐린 “예시” 스타일, 방문자가 만든 값은 진한 “내 것” 스타일. 입력은 서버 전송 없음 명시 | 무엇이 진짜인지 항상 구분 |
| DP-8 | 스크롤 연동 scale/blur/회전 | 칸 채움 글자 드러내기, 새싹 성장, 경로 재배치(FLIP), 문장이 카드로 날아가는 전환 — **모두 상태 변화** | 모션이 곧 피드백 |

### 의도적으로 가져오지 않은 것

- 스크롤로 화면을 붙잡는 고정 구간, 스크롤 연동 확대/흐림
- 거대한 숫자 전환 연출, 거대한 배경 인덱스 숫자
- 챕터 번호 내비와 전체 진행 막대(카드로 대체)
- 어두운 시네마틱 구간 (Vencubator의 밝은 온실 톤을 유지)

## 4. 시각 언어

- **온실 노트**: 옅은 모눈 종이 배경 + 인덱스 카드. v1의 밝은 녹색 계열 토큰을 쓰되 어두운 스테이지는 없다.
- **두 개의 목소리**: 서비스 문장은 Pretendard, **방문자가 쓴 문장은 명조(Gowun Batang)**로 표시해 “내 글”이 눈에 띄게 한다.
- **도장(스탬프)**: 상태는 `예시` `내 것` `가설 재검토` `결정` 도장으로 표시한다. 색만으로 구분하지 않고 글자를 함께 쓴다.
- 새싹 부캐는 v1과 같은 SVG 계열을 쓰되, 카드 위에서 **칸 수에 따라 5단계**로 자란다.

## 5. 미확정·가정

- 카드 내용은 프로토타입으로 넘어가지 않는다(다른 주소라서 저장소가 분리됨). CTA는 “문장 복사 후 프로토타입 열기”로 정직하게 처리했다. 실제 인계는 SPEC-007 DR-L2-01.
- 퀴즈·질문 템플릿은 prototype `LESSONS.customer`, `QUESTS.customer`와 같은 내용을 쓴다. AI 생성이 아니라 정해진 템플릿이다.
- 이 설계가 실제로 v1보다 나은지는 사용자 비교 연구가 필요하다(SPEC-007 §9).
